# JSON 切片协议

`architecture.json` 默认是唯一真相源。只有当单文件开始影响可维护性、上下文读取或多人/多会话协作时，才启用切片。切片不是把多个 JSON 随意散落在项目里，而是创建一个明确的 `architecture/` 架构文件夹，把真相源拆成“架构文件夹总索引 + 局部事实文件”。

切片模式下，推荐把 `architecture/index.json` 作为总索引。项目根目录的 `architecture.json` 可以保留为兼容入口或指针摘要，用来告诉智能体“本项目已启用架构文件夹，先读 `architecture/index.json`”。

## 启用条件

满足任一条件，可以启用切片：
- `architecture.json` 超过 1-2 MB，或模型读取明显变慢。
- 模块数量超过 30 个，或功能树叶子节点超过 100 个。
- 单次任务只涉及少数模块，但总 JSON 过大。
- 项目按业务域、前后端、插件、子系统长期并行迭代。
- 多会话或多人协作需要稳定分工，但仍要保留统一总索引。

不满足以上条件时，优先保持单 JSON。过早切片会增加同步成本。

## 架构文件夹

```text
architecture.json              # 兼容入口/指针摘要，可保留
architecture/
  index.json                   # 架构文件夹总索引，切片模式主入口
  features/
    f_user.json
  modules/
    m_user.json
  pages/
    p_dashboard.json
  data/
    users.json
  tasks/
    current-task.json
```

规则：
- 启用切片时必须创建 `architecture/` 文件夹。
- `architecture/index.json` 是切片模式的总索引。
- 根 `architecture.json` 若保留，只做兼容入口、摘要和指针，不承载大量细节。
- 不允许在项目任意位置散放架构切片；所有切片必须位于 `architecture/` 文件夹内。
- 如果暂时仍使用单 JSON，则不创建切片文件夹也可以。

创建新切片项目时，优先复用 `assets/architecture-folder-template/`：
- 把模板中的根 `architecture.json` 放到项目根目录。
- 把模板中的 `architecture/` 文件夹放到项目根目录。
- 再按实际项目补 `architecture/index.json` 和各类切片。

## 总索引字段

切片模式的总索引位于 `architecture/index.json`，至少包含项目身份、功能树摘要、模块树摘要、模块拓扑摘要、切片清单、上下文恢复点、未决问题和变更记录摘要。

根 `architecture.json` 推荐写成轻量指针：

```json
{
  "项目": {"名称": "项目名称"},
  "架构模式": "架构文件夹",
  "架构入口": "architecture/index.json",
  "说明": "本项目已启用 architecture/ 架构文件夹，请先读取 architecture/index.json"
}
```

`architecture/index.json` 示例：

```json
{
  "架构切片": {
    "启用": true,
    "架构模式": "架构文件夹",
    "总索引文件": "architecture/index.json",
    "根入口文件": "architecture.json",
    "切片目录": "architecture/",
    "切片清单": [
      {
        "编号": "m_user",
        "类型": "模块",
        "路径": "architecture/modules/m_user.json",
        "包含": ["模块详情", "接口契约", "实现清单", "完整细节", "测试责任矩阵"],
        "状态": "进行中",
        "更新时间": "2026-05-27T00:00:00+08:00"
      }
    ],
    "同步规则": [
      "总索引记录全局关系和切片位置",
      "切片记录局部细节",
      "跨切片依赖必须回写总索引的模块拓扑.依赖图",
      "每次修改切片必须更新总索引的更新时间和变更记录摘要"
    ]
  }
}
```

字段名必须中文。真实文件路径、代码标识符、路由、表名、字段名保留原样。

## 切片边界

| 切片类型 | 适合放什么 | 不应放什么 |
|----------|------------|------------|
| 功能切片 | 功能树子树、验收标准、异常路径、架构落位 | 模块完整实现细节 |
| 模块切片 | 模块详情、接口契约、实现清单、完整细节、测试责任 | 全局依赖图真相 |
| 页面切片 | 页面拓扑、组件树、交互状态、截图验收 | 后端业务规则真相 |
| 数据切片 | 表结构、索引、迁移、读写责任 | 服务层实现细节 |
| 任务切片 | 当前任务恢复点、失败恢复、未验证项 | 长期架构真相 |

## 同步规则

1. 总索引必须能回答：项目是什么、功能域有哪些、模块父子关系是什么、全局依赖是什么、切片在哪里。
2. 切片必须能回答：当前功能/模块/页面/数据的完整局部细节是什么。
3. 跨切片依赖只在总索引登记，不在两个切片里各写一份。
4. 切片内部修改必须更新切片自己的 `变更记录`，并在总索引追加摘要。
5. 删除或移动切片必须先更新总索引，再移动文件。
6. 若总索引与切片冲突，先走 `/校验架构` 分类；不能凭直觉选择一个覆盖另一个。

## 切片读取原则

- 开始任何任务先读总索引。
- 若根 `architecture.json` 指向 `architecture/index.json`，必须转读 `architecture/index.json`。
- 只读取本次影响范围内的切片。
- 需要跨模块判断时，读总索引的模块拓扑和相关模块切片摘要。
- 写代码时，只读当前模块切片的第3-4层和依赖模块切片的第2层。
- 收尾时更新当前切片、总索引、上下文恢复点和变更记录摘要。

## 切片迁移流程

从单 JSON 迁移到切片时：

1. 备份当前 `architecture.json`。
2. 创建 `architecture/` 文件夹和 `architecture/index.json`。
3. 在 `architecture/index.json` 中新增 `架构切片`，先标记 `"启用": false`。
4. 将根 `architecture.json` 改为兼容入口或保留完整备份，明确指向 `architecture/index.json`。
5. 按功能域或模块逐个抽出切片，不一次性全拆。
6. 每抽出一个切片，保留总索引摘要和切片路径。
7. 跑 JSON 解析和 21 项一致性校验。
8. 确认总索引与切片一致后，再把 `"启用": true`。
9. 在变更记录中写明迁移范围、校验结果和剩余风险。

## 回退流程

如果切片导致维护成本高于收益，可以回退：

1. 读取总索引和全部切片。
2. 合并为单个 `architecture.json`。
3. 将 `架构切片.启用` 设为 false，保留最近一次切片清单作为历史。
4. 跑 JSON 解析和 21 项一致性校验。
5. 写入变更记录，说明回退原因。
6. 可保留 `architecture/` 文件夹作为历史归档，但不得让智能体继续把它当作当前真相源。
