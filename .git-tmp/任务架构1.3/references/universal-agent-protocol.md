# 跨编程智能体通用协议

本协议用于让 Codex、Claude Code、Trae、Cursor、Windsurf、Cline、Continue、自研 CLI Agent 等任意编程智能体按同一套工程约束工作。它不是外部多智能体运行平台，也不要求平台原生支持子智能体；最低可用模式是单智能体结构化模拟。

## 最高裁决层

`architecture.json` 是唯一真相源。项目目标、验收标准、非目标和用户明确不要必须物化为 `architecture.json` 内部结构，不能作为 JSON 之上的独立自然语言裁决层。智能体必须先把本次任务落位到 JSON，再修改代码。

裁决优先级：

```text
用户明确不要
> 安全/数据/不可逆风险
> architecture.json 真相源
> 本次任务范围
> 智能体建议
> 执行速度
```

## 三层执行模式

| 等级 | 适用智能体 | 执行方式 |
|---|---|---|
| Level 1 单智能体结构化模拟 | 只能读提示词/改文件的编程智能体 | 用标准输出块模拟模块视角审议和门禁结果 |
| Level 2 增强单智能体 | 支持文件读写、shell、测试、脚本的智能体 | 在 Level 1 基础上运行校验脚本并记录证据 |
| Level 3 原生多智能体 | 支持 subagents/workers/多会话协作的平台 | 将模块智能体映射为真实执行单元，仍共享 `architecture.json` |

任何平台能力不足时，必须降级执行并记录原因；降级不能绕过 `architecture.json`、JSON 先行、验证证据和变更记录。

## 核心组件

- **JSON 内部目标摘要**：记录最终目标、阶段目标、验收标准、非目标、硬约束、成功证据和失败条件；它是 `architecture.json` 的内部字段，不是更高裁决层。
- **动态姿势语境**：记录当前阶段、风险、作用域、模块关系、触发事件、退出条件和追加门禁。
- **功能族引擎**：把需求展开为核心功能、天然绑定、商业标配、待确认扩展、跨模块提案和明确排除。
- **模块智能体协议**：按模块边界组织审议和实现责任。
- **接口契约池**：跨模块协作必须通过接口契约和影响范围分析。
- **硬约束门禁**：用状态门禁阻止跳步、越界、无证据完成。
- **证据账本**：记录自动化测试、人工检查、未验证项、恢复点和变更记录。

## 最小闭环

```text
用户需求
→ 需求落位到 architecture.json
→ 动态姿势语境
→ 功能族展开
→ 模块智能体提案
→ 接口契约/影响范围
→ 硬约束门禁
→ architecture.json 变更
→ 代码/文档/测试变更
→ 验证证据
→ 上下文恢复点和变更记录
```

## 平台无关约束

- 不得把协议写成单一平台专用规则。
- 不得因平台没有脚本能力而跳过 JSON 先行；只能记录无法运行工具。
- 不得因平台支持多智能体而让子智能体绕过 `architecture.json`。
- 不得让功能族展开结果直接进入实现；必须经过模块边界和门禁裁决。
- 不得让适配层覆盖核心协议。

## 智能体能力探测

进入新平台或新项目时，智能体应先识别自身能力；结果只作为执行降级依据，不写成新的项目真相源。

```json
{
  "智能体能力": {
    "可读写文件": true,
    "可运行命令": true,
    "可调用浏览器": false,
    "可维护长期记忆": false,
    "支持子智能体": false,
    "支持规则文件": true,
    "支持工具调用": true,
    "支持结构化输出": true
  }
}
```

## 降级规则

- 无法运行脚本：按文本规则手工检查，并记录“工具未运行”和原因。
- 无法维护长期记忆：必须把恢复点写入 `architecture.json.上下文恢复点`。
- 无法使用子智能体：用结构化输出模拟模块智能体。
- 无法使用浏览器或截图：记录未验证视觉风险或替代检查。
- 无法编辑文件：只能输出变更计划，不得声称已完成实现。

平台适配说明放在 `adapters/`，只记录平台差异和降级方式，不重复核心协议全文。
