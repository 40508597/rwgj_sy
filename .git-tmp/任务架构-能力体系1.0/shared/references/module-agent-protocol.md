# 模块智能体协议

模块智能体是按模块边界组织的虚拟或真实执行单元。它不是职业角色，不以“架构师/工程师/测试员”为目标，而以模块职责、接口契约和 `architecture/index.json` 及相关切片中已登记的 `项目.说明`、功能树与模块详情为边界。

## 模块智能体定义

```json
{
  "智能体编号": "agent_auth",
  "负责模块": "m_auth",
  "模块目标": "",
  "可修改范围": [],
  "只读依赖": [],
  "可导出接口": [],
  "禁止事项": [],
  "完成条件": []
}
```

## 执行边界

模块智能体可以：

- 读取根指针 `architecture.json` 后，转读 `architecture/index.json`、功能切片、所属模块详情、上游接口契约和下游消费者；如本次任务已有动态姿势语境，则读取任务态语境或 `architecture/tasks/state.json.上下文恢复点.动态姿势语境`。
- 使用功能族展开本模块应承担的能力。
- 提出模块内变更、接口变更、跨模块提案和验证责任。
- 修改已登记到本模块实现清单的文件。

模块智能体不得：

- 直接修改非所属模块文件。
- 绕过接口契约调用其他模块内部结构。
- 私自改变公共接口。
- 将待确认扩展直接实现。
- 把功能族候选当作已确认需求。

## 功能族使用

每个模块智能体都可以使用功能族，但必须分类：

```json
{
  "功能族展开": {
    "核心功能": [],
    "天然绑定功能": [],
    "商业标配功能": [],
    "待确认扩展": [],
    "跨模块提案": [],
    "明确排除": []
  }
}
```

跨模块提案只能进入提案池和接口契约池，不得直接实现。

## 模块提案输出

模块智能体输出必须符合 `references/agent-output-contract.md`。最低要求包含：输出类型、关联语境、负责范围、结论、功能族展开、变更提案、接口影响、风险、验证责任、证据和下一步。
