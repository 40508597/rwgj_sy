# 执行模板

这些模板用于提高技能执行稳定性。它们不改变架构内容，只约束智能体每轮如何开始、如何汇报架构变更、如何判断完成、失败时如何恢复。

## 任务前置输出模板

每次进入受管项目任务，第一段输出必须先给出以下内容。没有完成这段判定前，不要创建文件、修改代码或扩大业务范围。

```text
任务判定：
- 自动判定命令：/分析架构 | /创建架构 | /修改架构 | /追加架构 | /校验架构
- 用户本次需求锁定：明确要做什么；明确不要做什么；验收信号是什么
- 本次细节清单：页面/按钮/字段/API/CLI/后台任务/运行形态/入口/交付物/系统集成/数据表/文案/状态/异常/文件/测试
- 是否发现根指针 `architecture.json`：是/否，路径：
- 架构入口解析：若 `架构入口=architecture/index.json`，已转读总索引：是/否
- 是否为受管项目：是/否
- 本次是否必须先更新架构切片：是/否，原因：
- 本次需要读取的架构层级：第1层/第2层/第3层/第4层/横向追踪层
- 本次影响范围：功能树节点、模块树节点、模块、运行形态、入口、接口、数据、交付物、系统集成、文件、测试
- 本次最小闭环：架构变更 → 代码变更 → 验证 → 恢复点/变更记录
- 用户明确约束：列出；没有则写“无”
- 待确认问题：列出；没有则写“无”
```

要求：
- 自动判定命令必须明确，不能写“可能是”。
- 用户本次需求锁定必须先于功能扩展；不得把用户没要的扩展混入本次实现。
- 本次细节清单必须逐项落位；不能只写“优化 UI”“修复 Bug”这类概括。
- 如果根指针 `architecture.json` 存在，默认是受管项目；不得在根指针里寻找功能树、模块拓扑或恢复点，必须转读 `architecture/index.json` 和相关切片。
- 若用户要求跳过架构文件夹，必须在“是否必须先更新架构切片”处标记跳过原因和漂移风险。
- 如果无法判定命令，只问一个澄清问题，不得先改代码。

## 注意力预算

每次任务按以下顺序分配注意力：
1. 用户本次明确需求、限制和验收信号。
2. 与需求直接相关的架构节点和代码文件。
3. 直接依赖和直接下游影响。
4. 必要校验和恢复记录。
5. 更远的架构扩展、治理建议和切片迁移。

默认不要把第5项提前。除非用户要求架构治理、切片迁移或全局评估，否则不要展开全局优化建议。

禁止：
- 为了完整性读取全部 reference。
- 为了保险读取全部模块切片。
- 为了展示能力扩展用户未要求的功能。
- 用流程性汇报替代对用户细节的实现和验证。
- 忽略用户的小细节，例如一个字段名、一个按钮状态、一句文案、一个异常路径。

## 架构修改前后对比模板

每次修改 `architecture/index.json` 或切片文件后，必须给出结构化对比。不要只说“已更新架构”。

```text
架构变更对比：
- 新增：
  - 功能树：
  - 模块树：
  - 模块拓扑：
  - 模块详情：
  - 接口契约：
  - 实现清单：
  - 完整细节：
  - 测试责任矩阵：
  - 验证证据：
- 修改：
  - 字段/节点：
  - 修改原因：
  - 影响范围：
- 废弃：
  - 字段/节点：
  - 废弃原因：
  - 替代位置：
- 必须同步的代码/测试：
- 已写入变更记录：是/否
- 已更新上下文恢复点：是/否
```

要求：
- 没有新增/修改/废弃时写“无”，不要省略字段。
- 涉及接口、数据表、路由、权限、状态机时，必须列出下游影响。
- 涉及切片文件时，必须同时说明总索引是否更新。

## 变更类型矩阵

常见变更必须同步更新对应架构区域。

| 变更类型 | 必须更新 | 必须验证 |
|----------|----------|----------|
| 新增页面/界面 | 功能树、运行形态、入口.用户入口、页面拓扑、模块树、实现清单、完整细节、测试责任矩阵、验证证据、变更记录 | 路由/窗口/视图入口、交互状态、截图/真实渲染验收 |
| 删除页面元素 | 功能树或完整细节、页面拓扑、验证证据、变更记录 | 页面不再显示、相关交互不破坏 |
| 新增 API/RPC/WebSocket/SDK入口 | 功能树、入口.接口入口、模块树、模块拓扑、模块详情、接口契约、实现清单、测试责任矩阵、变更记录 | 契约测试、异常路径、依赖完整性 |
| 修改 API 签名 | 接口契约、模块拓扑、模块详情、下游调用方、测试责任矩阵、变更记录 | 所有下游调用点和契约测试 |
| 新增后台任务/系统入口 | 功能树、入口.系统入口、模块树、模块详情、接口契约、实现清单、测试责任矩阵、验证证据、变更记录 | 触发方式、生命周期、重试、失败告警、幂等性、权限边界 |
| 新增 CLI/脚本命令 | 功能树、入口.命令入口、模块树、模块详情、接口契约、实现清单、测试责任矩阵、变更记录 | 参数、退出码、错误输出、帮助信息 |
| 新增交付物 | 功能树、运行形态、交付物、实现清单、模块详情配置/安全边界、测试责任矩阵、验证证据、变更记录 | 构建命令、产物路径、启动 smoke test、安装/卸载/发布/回滚、签名或未签名风险、自动更新策略 |
| 新增系统集成 | 功能树、入口.系统入口、系统集成、模块详情、安全边界、实现清单、测试责任矩阵、验证证据、变更记录 | 权限申请、失败降级、系统兼容性、真实环境或替代环境验证 |
| 修改字段/表结构 | 数据拓扑、接口契约、实现清单、迁移脚本、测试责任矩阵、变更记录 | 迁移、读写路径、回归测试 |
| 修 Bug | 功能树异常路径、模块详情错误边界、完整细节测试用例、测试责任矩阵、验证证据、变更记录 | 复现测试、修复测试、回归测试 |
| 性能优化 | 模块详情性能约束、完整细节实现约束、验证证据、变更记录 | 性能证据或未验证说明 |
| 重构模块 | 模块树、模块拓扑、模块详情、接口契约、实现清单、测试责任矩阵、变更记录 | 依赖图无环、下游调用、回归测试 |
| 新增依赖库 | 项目、模块详情配置/安全边界、实现清单、验证证据、变更记录 | 安装/构建/安全影响 |
| 修改 UI 设计 | 功能树、页面拓扑、完整细节、专业能力索引回写、验证证据、变更记录 | 响应式、图标语义、截图/浏览器验收 |

## 完成定义

每次任务完成前，必须逐项自查：

```text
完成定义：
- 架构已先于代码更新；若未先更新，已记录流程违规和修复动作
- 用户本次需求锁定中的每个细节都已落到架构文件夹、代码或明确未完成/不处理原因
- 功能树叶子节点已可验收、可落位、可测试
- 模块树父子关系、模块拓扑依赖关系、模块详情边界一致
- 接口契约、实现清单、完整细节与代码一致
- 测试责任矩阵覆盖本次正常路径、边界路径和异常路径
- 验证证据已记录命令、结果、截图/浏览器验收或未验证项
- 上下文恢复点已更新，下一轮能继续
- 变更记录已追加，包含原因、影响范围、验证结果和剩余风险
- 已运行 21 项一致性校验或说明无法运行的原因
- 最终汇报包含剩余风险，不把未验证项说成已完成
```

未满足完成定义时，不得声称任务完成。可以汇报“已完成设计/实现，未完成验证”，并把缺口写入 `上下文恢复点.未验证项` 和 `变更记录.剩余风险`。

## 失败恢复模板

当测试失败、实现卡住、依赖缺失、上下文将中断或需要等待用户时，必须写入失败恢复信息。

```json
{
  "失败恢复": {
    "失败阶段": "分析 | 设计 | 架构更新 | 实现 | 测试 | 校验 | 收尾",
    "失败位置": "模块/文件/接口/测试/命令",
    "失败现象": "具体错误或阻塞",
    "已完成": [],
    "未完成": [],
    "已确认事实": [],
    "不要重复": [],
    "下一步建议": [],
    "需要用户确认": [],
    "临时风险": [],
    "更新时间": "ISO 8601 时间"
  }
}
```

写入位置：
- 优先写入 `上下文恢复点` 的对应字段。
- 如果项目启用切片，写入当前任务切片或当前模块切片，并在总索引记录位置。
- 最终汇报必须复述失败位置、下一步和未验证项。
