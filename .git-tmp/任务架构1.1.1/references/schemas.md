# architecture.json 四层递进 Schema

> **核心原则**：AI 做不同任务时读不同深度。加新功能只读第1-2层，写模块代码才读第3-4层。避免一股脑把全部细节塞进上下文。

> **中文化原则**：architecture.json 的对象键名、说明字段、状态值、测试描述和变更记录必须使用中文。真实代码标识符、文件路径、路由路径、HTTP 方法、数据库表名/字段名、技术栈名和第三方库名保留原样，避免破坏代码契约。

---

## 第2层：接口契约

**何时读取**：需要调用已有模块时。写新模块代码时，只读它依赖模块的第2层。

```json
{
  "接口契约": {
    "m6": {
      "模块名": "auth",
      "导出": [
        {
          "名称": "authenticate",
          "签名": "(username: str, password: str) -> User | None",
          "说明": "验证用户名密码，成功返回 User 对象，失败返回 None",
          "可能异常": ["DatabaseError（数据库不可用）"]
        },
        {
          "名称": "create_session",
          "签名": "(user_id: UUID) -> Session",
          "说明": "为用户创建会话，返回 Session 对象含 token",
          "可能异常": ["DatabaseError"]
        },
        {
          "名称": "validate_session",
          "签名": "(token: str) -> User | None",
          "说明": "验证会话 token，返回对应用户，过期或无效返回 None",
          "可能异常": []
        },
        {
          "名称": "destroy_session",
          "签名": "(token: str) -> None",
          "说明": "销毁会话（登出），token 不存在时静默成功",
          "可能异常": []
        },
        {
          "名称": "hash_password",
          "签名": "(password: str) -> str",
          "说明": "对密码进行 bcrypt 哈希",
          "可能异常": []
        }
      ],
      "依赖": [
        {"模块编号": "m4", "使用接口": ["get_session"]},
        {"模块编号": "m2", "使用接口": ["log_info", "log_warning"]}
      ]
    }
  }
}
```

**作用**：AI 知道"我能调用什么、怎么调用、可能出什么错"。加账号系统时读第2层就知道 auth 模块已有 `authenticate/create_session/validate_session`，不需要重写。

## 第3层：实现清单

**何时读取**：开始写一个具体模块的代码时。包含文件路径、数据表 DD、组件树骨架。

```json
{
  "实现清单": {
    "m6": {
      "文件列表": [
        {"路径": "src/auth/__init__.py", "说明": "模块入口，导出所有公开接口"},
        {"路径": "src/auth/service.py", "说明": "认证服务：authenticate/create_session/validate_session/destroy_session"},
        {"路径": "src/auth/password.py", "说明": "密码处理：hash_password/verify_password"},
        {"路径": "src/auth/models.py", "说明": "数据模型：User/Session ORM 类"}
      ],
      "关联数据表": [
        {
          "表名": "users",
          "字段": [
            {"名称": "id", "类型": "UUID", "约束": "PRIMARY KEY DEFAULT gen_random_uuid()"},
            {"名称": "username", "类型": "VARCHAR(100)", "约束": "NOT NULL UNIQUE"},
            {"名称": "password_hash", "类型": "VARCHAR(255)", "约束": "NOT NULL", "敏感": true},
            {"名称": "created_at", "类型": "TIMESTAMP", "约束": "NOT NULL DEFAULT now()"}
          ],

          "迁移": "migrations/002_create_users.sql"

            {"名称": "token", "类型": "VARCHAR(255)", "约束": "PRIMARY KEY"},
            {"名称": "user_id", "类型": "UUID", "约束": "NOT NULL REFERENCES users(id)"},

    "p1": {
      "路由路径": "/login",
      "组件树": [
        {
          "名称": "LoginPage",
          "类型": "page",
          "子组件": [
```

## 四层读取策略

| 任务 | 需要读 | 因为 |
|------|--------|------|
| 加新功能（定位） | 仅第1层 | 先理解骨架，判断新模块应该插在哪 |
| 加新功能（设计接口） | 第1-2层 | 知道依赖哪些已有接口，设计新接口 |
| 写模块代码 | 第1-3层 | 知道文件清单、数据表、组件树 |
| 写具体函数/组件 | 第1-4层中本模块部分 | 不读其他模块的第4层 |
| 调试 | 第1层 + 相关模块的第2层 + 具体位置的第4层 | 追溯调用链，查接口契约 |
| 重构/优化 | 第1-2层 + 目标模块的第3-4层 | 改接口时查所有下游 |

**关键规则**：永远不要一次性把第4层的全部内容喂给 AI。只传当前任务相关的模块的第4层。

## 完整性检查清单

生成 architecture.json 后逐项检查：

```
第1层检查：
  □ 项目类型/语言/框架已确定  □ 入口路由树/命令树完整
  □ 模块拓扑包含所有模块（基础设施+业务）  □ 依赖图无循环
  □ 页面拓扑列出所有页面  □ 数据拓扑列出所有表

第2层检查：
  □ 每个模块的导出接口有完整签名  □ 每个模块的依赖精确到"使用接口"
  □ 每个接口的可能异常不为空  □ 没有隐式依赖

第3层检查：
  □ 每个模块文件数 1-5 个  □ 每张表字段/约束/索引/迁移完整
  □ 每个页面有组件树  □ 每个组件树展开到可编写级别

第4层检查：
  □ 每个接口有完整参数说明+实现约束+测试用例
  □ 每个组件有属性列表+交互事件链+五态展示
  □ 测试用例覆盖：正常+边界+异常（至少各一）
```
