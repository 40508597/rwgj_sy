# 关键规则

### 先判定，再行动

每次调用技能后，第一段输出必须先给出任务判定和范围边界。没有完成判定前，不要创建文件、修改代码或扩展业务范围。

### 受管项目必须自动接管

当前项目存在 `architecture.json` 时，默认已经进入任务架构管理。任何代码、UI、接口、数据、测试、文件或行为修改，都必须先更新 `architecture.json`，再改代码。用户没有显式输入 `/修改架构` 不是绕过 JSON 的理由。

如果用户明确要求跳过 JSON，必须说明代码漂移风险，并在最终汇报和变更记录中标出“本次未更新 architecture.json”。

### 接口即合同

模块的"导出"是对下游的承诺。修改导出接口时，必须检查所有依赖链上的模块，受影响模块状态重置为"计划中"。

### 变更记录不可省略

每次修改 JSON 必须在变更记录中追加：时间、操作类型、原因、影响范围。即使只改一行代码的 Bug，也要留痕。

### 修改后一致性自动校验

**每次修改 architecture.json 后，必须立即执行以下 21 项校验，不得跳过。校验结果写入变更记录。**

```
校验1：依赖完整性
  遍历所有模块的 依赖.使用接口 → 检查目标模块的 导出 中是否存在该接口
  → 不存在 = 悬空依赖，必须修复

校验2：路由-页面对应
  遍历入口路由中所有路径 → 检查是否有对应的页面拓扑节点
  → 缺失 = 路由指向空白页

校验3：接口-实现对应
  遍历接口契约中所有导出接口 → 检查实现清单中是否有对应的文件
  → 缺失 = 接口只有声明没有实现

校验4：数据表-迁移对应
  遍历数据拓扑中所有表 → 检查是否有迁移脚本路径
  → 缺失 = 表无法创建

校验5：需登录页面-认证依赖
  遍历入口路由中标记"需登录"的路径 → 检查对应页面是否依赖了认证模块
  → 缺失 = 页面缺少认证保护

校验6：测试覆盖异常
  遍历接口契约中每个接口的 可能异常 → 检查完整细节中测试用例是否覆盖了每个异常
  → 缺失 = 异常路径无测试覆盖

校验7：依赖图无环
  从模块拓扑的依赖图检测是否存在循环依赖
  → 存在 = 架构错误，必须重构

校验8：交互完整性
  遍历本次涉及的所有组件/接口/命令
  → 检查是否有交互完整性检查记录
  → 检查是否有未通过的检查项（不含"不适用"）
  → 有未通过项 = 设计不完整，必须补全

校验9：代码漂移
  遍历本次新增/修改的文件、接口、路由、命令、数据结构
  → 检查是否都已登记到 architecture.json 的对应层级
  → 代码有、JSON 无 = 漂移，必须先补 JSON

校验10：变更可追踪
  检查本次变更是否写入变更记录，且包含原因、影响范围、验证结果、剩余风险
  → 缺失 = 黑盒变更，必须补记录

校验11：入口类型清晰
  遍历入口结构
  → 必须按 用户入口、接口入口、命令入口、事件入口、系统入口、资源入口 分开登记
  → 不得新增 页面路由/API路由/静态资源路由/CLI命令树/后台任务/桌面窗口/桌面菜单栏/托盘入口/本地协议/文件关联/系统通知 等入口主键
  → 混用入口主键 = 校验规则会误判，必须拆分到通用入口类型

校验12：异常契约测试
  遍历接口契约中每个接口的 可能异常
  → 检查完整细节或测试责任矩阵中是否有对应测试场景
  → 无法真实触发时，必须说明 mock/monkeypatch/替身注入方式
  → 缺失 = 契约假闭环，必须补测试或补说明

校验13：验证证据完整
  检查本次完成项是否记录自动化测试、架构校验、浏览器验收、截图、手动检查或未验证项
  → 只写"已验证"但无证据 = 追踪不足，必须补验证证据

校验14：上下文恢复点完整
  检查 architecture.json 是否记录当前任务、当前阶段、继续位置、下一步、用户明确约束、未验证项、剩余风险
  → 缺失 = 压缩/中断后无法可靠续跑，必须补上下文恢复点

校验15：功能树落位完整
  遍历功能树中状态为"已确认"或"进行中"的叶子节点
  → 检查是否记录验收标准、异常路径、架构落位、验证责任
  → 架构落位至少要指向模块，并按实际形态指向入口/接口/数据/文件/测试
  → 涉及运行形态、交付物或系统集成的功能必须同时指向对应入口、交付物或系统集成节点
  → 缺失 = 功能只停留在需求清单，必须补落位；暂不实现的节点必须标为"待确认"或"延期"

校验16：专业能力索引边界
  检查专业能力索引是否只记录能力类型、触发信号、调用建议、回写位置和边界
  → 不得把外部技能写成强制依赖，不得让专业能力索引接管任务流程
  → 若本次调用了 UI/测试/安全/性能/桌面端/可执行交付/部署/文档等专业能力，检查产出是否回写到 architecture.json
  → 缺失 = 专业能力游离在真相源之外，必须补回写位置或删除越权内容

校验17：UI设计与图标库质量
  遍历功能树、页面拓扑和完整细节中涉及页面/组件/仪表盘/管理后台/编辑器/移动端/桌面端界面的节点
  → 检查是否记录设计系统或视觉方向、组件状态、响应式责任、图标库/图标语义、截图或浏览器验收责任
  → 如果项目已有图标库，检查是否优先使用已有图标库；没有图标库时，必须说明选择、暂不引入或待用户确认
  → 缺失 = UI 只停留在可用层面，必须补设计感、图标系统和验收责任；不得声称 UI 已完成

校验18：受管项目 JSON 先行
  检查当前项目是否存在 architecture.json
  → 若存在，检查本次代码/UI/接口/数据/测试/文件/行为修改之前是否已更新 architecture.json
  → 若未先更新 JSON，必须标记为流程违规，补写 JSON 变更、影响范围、验证证据和变更记录
  → 若用户明确要求跳过 JSON，必须记录跳过原因和代码漂移风险

校验19：模块详情完整
  遍历模块拓扑中的每个模块节点
  → 检查模块详情中是否存在对应模块编号
  → 至少记录职责、非职责、所属功能树节点、上游依赖/下游消费者、内部结构、数据读写责任、错误边界、配置项、安全边界、测试责任
  → 无状态/无配置/无性能要求的模块必须明确写“不适用”，不得留空
  → 缺失 = 模块边界不清，容易职责漂移，必须补模块详情后再实现或修改代码

校验20：模块树层级完整
  遍历模块树中的每个节点和子节点
  → 检查每个节点是否记录编号、名称、层级、父模块、子模块、职责、落位
  → 子模块的父模块必须指向真实存在的父节点；根模块父模块写 null 或“不适用”
  → 模块树不得出现父子循环；跨分支依赖必须写入模块拓扑.依赖图，不得藏在子模块关系里
  → 已确认或进行中的叶子模块必须在模块详情、实现清单、测试责任矩阵中有对应记录，或明确标为“待设计/待实现/延期”
  → 缺失 = 模块只有扁平列表，没有下属模块颗粒度，必须补模块树后再实现或修改代码

校验21：架构切片同步
  若 架构切片.启用 为 true：
  → 检查是否存在 architecture/ 架构文件夹和 architecture/index.json 总索引
  → 检查总索引是否包含架构模式、根入口文件、切片目录、切片清单、同步规则
  → 切片清单中的路径必须位于 architecture/ 文件夹内，真实存在，类型必须清晰，状态和更新时间必须存在
  → 修改切片时，总索引必须同步更新时间、切片状态和变更记录摘要
  → 跨切片依赖必须登记在总索引 模块拓扑.依赖图 中
  → 总索引与切片冲突时必须走 /校验架构 分类，不得直接覆盖
  → 缺失 = 切片真相源分裂，必须先同步总索引和切片再继续
```

**校验结果格式**（写入变更记录的影响范围字段）：
```
"影响范围": "m3, m5 | 校验通过: 21/21" 或 "m3 | 校验未通过: 校验3(接口无实现), 校验6(异常无测试), 校验11(入口类型混用), 校验15(功能树未落位或交付物/系统集成未落位), 校验16(专业能力未回写), 校验17(UI/客户端界面缺少图标库或截图验收), 校验18(受管项目未先改JSON), 校验19(模块详情缺失), 校验20(模块树层级缺失), 校验21(架构文件夹/切片未同步)"
```

### 禁止事项

以下任一信号出现，说明设计停留在 Demo 层面：
- 没有配置管理模块（硬编码URL）
- 没有错误处理模块（各自try-catch，返回格式不一致）
- 没有日志模块（靠print排查）
- 没有数据校验（假设输入总是合法）
- 没有数据库迁移（手动建表）
- 测试用例只有happy path
- 模块依赖图有循环
- 接口定义只有成功返回没有异常

### 精细化程度标准

**唯一判断标准：一个不熟悉项目的开发者，拿到 architecture.json 后，能否独立写出完整的可运行代码？** 能→够了。不能→继续细化。
