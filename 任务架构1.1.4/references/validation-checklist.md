# 关键规则

### 先判定，再行动

每次调用技能后，第一段输出必须先给出任务判定和范围边界。没有完成判定前，不要创建文件、修改代码或扩展业务范围。

### 接口即合同

模块的"导出"是对下游的承诺。修改导出接口时，必须检查所有依赖链上的模块，受影响模块状态重置为"计划中"。

### 变更记录不可省略

每次修改 JSON 必须在变更记录中追加：时间、操作类型、原因、影响范围。即使只改一行代码的 Bug，也要留痕。

### 修改后一致性自动校验

**每次修改 architecture.json 后，必须立即执行以下校验，不得跳过。校验结果写入变更记录。**

```
校验1：依赖完整性
  遍历所有模块的 依赖.使用接口 → 检查目标模块的 导出 中是否存在该接口
  → 不存在 = 悬空依赖，必须修复

校验2：路由-页面对应
  遍历入口路由中所有路径 → 检查是否有对应的页面拓扑节点
  → 缺失 = 路由指向空白页

校验3：接口-实现对应
  遍历接口契约中所有导出接口 → 检查实现清单中是否有对应的文件
  → 缺失 = 接口只有声明没有实现

校验4：数据表-迁移对应
  遍历数据拓扑中所有表 → 检查是否有迁移脚本路径
  → 缺失 = 表无法创建

校验5：需登录页面-认证依赖
  遍历入口路由中标记"需登录"的路径 → 检查对应页面是否依赖了认证模块
  → 缺失 = 页面缺少认证保护

校验6：测试覆盖异常
  遍历接口契约中每个接口的 可能异常 → 检查完整细节中测试用例是否覆盖了每个异常
  → 缺失 = 异常路径无测试覆盖

校验7：依赖图无环
  从模块拓扑的依赖图检测是否存在循环依赖
  → 存在 = 架构错误，必须重构

校验8：交互完整性
  遍历本次涉及的所有组件/接口/命令
  → 检查是否有交互完整性检查记录
  → 检查是否有未通过的检查项（不含"不适用"）
  → 有未通过项 = 设计不完整，必须补全

校验9：代码漂移
  遍历本次新增/修改的文件、接口、路由、命令、数据结构
  → 检查是否都已登记到 architecture.json 的对应层级
  → 代码有、JSON 无 = 漂移，必须先补 JSON

校验10：变更可追踪
  检查本次变更是否写入变更记录，且包含原因、影响范围、验证结果、剩余风险
  → 缺失 = 黑盒变更，必须补记录

校验11：入口类型清晰
  遍历入口结构
  → 页面路由、API路由、静态资源路由、CLI命令、后台任务、事件入口必须分开登记
  → 混用 = 校验规则会误判，必须拆分入口类型

校验12：异常契约测试
  遍历接口契约中每个接口的 可能异常
  → 检查完整细节或测试责任矩阵中是否有对应测试场景
  → 无法真实触发时，必须说明 mock/monkeypatch/替身注入方式
  → 缺失 = 契约假闭环，必须补测试或补说明

校验13：验证证据完整
  检查本次完成项是否记录自动化测试、架构校验、浏览器验收、截图、手动检查或未验证项
  → 只写"已验证"但无证据 = 追踪不足，必须补验证证据

校验14：上下文恢复点完整
  检查 architecture.json 是否记录当前任务、当前阶段、继续位置、下一步、用户明确约束、未验证项、剩余风险
  → 缺失 = 压缩/中断后无法可靠续跑，必须补上下文恢复点

校验15：功能树落位完整
  遍历功能树中状态为"已确认"或"进行中"的叶子节点
  → 检查是否记录验收标准、异常路径、架构落位、验证责任
  → 架构落位至少要指向模块，并按实际形态指向入口/接口/数据/文件/测试
  → 缺失 = 功能只停留在需求清单，必须补落位；暂不实现的节点必须标为"待确认"或"延期"
```

**校验结果格式**（写入变更记录的影响范围字段）：
```
"影响范围": "m3, m5 | 校验通过: 15/15" 或 "m3 | 校验未通过: 校验3(接口无实现), 校验6(异常无测试), 校验15(功能树未落位)"
```

### 禁止事项

以下任一信号出现，说明设计停留在 Demo 层面：
- 没有配置管理模块（硬编码URL）
- 没有错误处理模块（各自try-catch，返回格式不一致）
- 没有日志模块（靠print排查）
- 没有数据校验（假设输入总是合法）
- 没有数据库迁移（手动建表）
- 测试用例只有happy path
- 模块依赖图有循环
- 接口定义只有成功返回没有异常

### 精细化程度标准

**唯一判断标准：一个不熟悉项目的开发者，拿到 architecture.json 后，能否独立写出完整的可运行代码？** 能→够了。不能→继续细化。
