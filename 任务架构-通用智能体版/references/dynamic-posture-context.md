# 动态姿势语境协议

动态姿势语境用于描述智能体当前处在什么工程状态。它不是角色身份，也不是多智能体调度结果，而是影响读取范围、功能族展开深度、模块行为、硬门禁和验证责任的状态系统。

## 标准结构

完整结构只用于中大型任务、跨模块任务、高风险任务、交付任务或跨会话恢复。小任务不得强制输出完整 JSON。

```json
{
  "姿势语境": {
    "版本": "1.0",
    "语境编号": "ctx_001",
    "作用域": "全局 | 模块 | 接口 | 数据 | UI | 交付 | 恢复",
    "当前阶段": "需求锁定 | 架构设计 | JSON更新 | 实现 | 验证 | 收尾 | 恢复 | 阻塞",
    "任务类型": ["新增功能"],
    "执行模式": ["规划", "模块设计", "实现", "审查", "修复", "风险控制"],
    "专业语境": ["UI", "接口", "数据", "安全", "测试", "性能", "部署"],
    "风险等级": "低 | 中 | 高 | 阻塞",
    "触发事件": [],
    "生效原因": [],
    "适用模块": [],
    "模块关系": {
      "主改模块": [],
      "受影响模块": [],
      "只读依赖模块": [],
      "下游消费者": []
    },
    "必须读取": [],
    "必须校验": [],
    "硬约束追加": [],
    "禁止事项": [],
    "功能族展开策略": {
      "展开深度": "浅 | 中 | 深",
```

## 分级使用

| 任务规模 | 输出形式 | 适用场景 |
|---|---|---|
| 小任务 | 一句话语境 | 改文案、改样式、小 Bug、单文件内部调整 |
| 中任务 | 精简 JSON | 单模块功能修改、接口小改、普通 UI/数据变更 |
| 大任务 | 完整 JSON | 新功能、跨模块变更、高风险操作、交付发布、恢复续跑 |

### 小任务语境

```text
阶段=实现；风险=低；作用域=m_ui；禁止=不碰无关模块；校验=页面显示/相关测试。
```

### 中任务语境

```json
{
  "当前阶段": "实现",
  "风险等级": "中",
  "适用模块": ["m_export"],
  "受影响模块": ["m_auth"],
  "必须校验": ["权限", "失败反馈"],
  "禁止事项": ["跳过 JSON", "顺手改无关模块"],
  "退出条件": ["验证证据已记录"]
}
```

### 大任务语境

大任务使用完整结构，并把必要字段写入 `architecture.json.上下文恢复点`。只有跨会话、长任务或高风险任务才需要持久化完整语境。

## 动态触发

| 触发事件 | 语境变化 |
|---|---|
| 用户需求模糊 | 进入需求锁定和功能族展开语境 |
| 发现 `architecture.json` | 进入受管项目语境 |
| 新增模块或功能 | 进入架构设计和模块设计语境 |
| 修改接口签名 | 进入接口契约和下游影响语境 |
| 涉及删除、迁移、权限、生产数据 | 进入高风险语境 |
| 开始修改代码 | 进入实现语境 |
| 测试失败 | 进入修复语境，冻结无关扩展 |
| 准备构建、发布、打包 | 进入交付语境 |
| 上下文中断或用户说继续 | 进入恢复语境 |

## 硬规则

- 每次语境变化必须有触发事件。
- 语境可以追加约束，不能移除核心硬约束。
- 高风险语境优先级高于普通实现语境。
- 修复语境禁止顺手重构和无关扩展。
- 恢复语境必须先读取恢复点和最近变更记录。
- 语境退出必须满足明确退出条件。
- 小任务不强制完整 JSON；如果完整语境开始挤压实现和验证，应降级为一句话或精简 JSON。
