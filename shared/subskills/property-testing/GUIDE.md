# 属性与不变量测试

适用于存在可说明的逆变换、保持条件、规范化或独立参考结果的逻辑，例如序列化、解析、金额、排序与状态转换。
输入：函数/契约、合法输入域、边界、已知性质及现有测试工具。
产出：有业务意义的性质、输入生成范围、最小反例和真实运行证据；不适合属性测试也是有效判断。

## 性质与输入域
- 从契约推导性质：往返保留、幂等、顺序关系、前后不变量或独立参考等价；先明确损失信息、舍入和容差规则。
- 性质须能捕获错误而非复述实现。纯函数把同一表达式与自己比较通常恒真；具有外部变化的函数需明确确定性条件。
- 约束合法输入直接放入生成策略，检查过滤是否使绝大多数或全部样本被排除；记录实际有效样本。
- 覆盖零、空、边界长度、极值、重复与序列关系，但仅加入契约允许或要求拒绝的输入。
- 没有可测边界时先找可分离的纯逻辑或状态观察点；重构收益与成本需符合当前任务范围。
- 性质失败后保留原输入与缩减反例，判断是生成器/性质理解错误、环境依赖还是生产缺陷，分别处理。
- 用反例回归和少量独立预期样本交叉检查；两端同样错误的往返实现仍可能通过，不能因此声称整体正确。
- 使用项目现有工具或可执行的确定性输入集。无适用生成器时保留方法性审查与缺口，不假装已运行任意语言的属性引擎。

## 回写与证据
性质、输入域和负责模块写 `/测试责任矩阵` 或 `/完整细节`，运行与最小反例写 `/验证证据`。
review 是设计或审查；execution 需要当前输入、参数/种子及真实收据。新增依赖服从既有授权，不由来源技能自动安装。
性质强度取决于契约，不把形式排序当作所有项目的质量评分。
