# Web交互与可访问性审查

仅在当前项目存在真实Web界面、并涉及交互或可访问性检查时使用。规则按固定快照审查，需更新时另核对版本。
输入：当前页面/组件、行为与状态、已有设计规范、运行工具条件和审查范围。
产出：具体文件/组件位置、可观察影响、修复方向和未验证的辅助技术行为，允许零发现。

## 检查可操作与可理解
- 优先语义控件：动作、导航、标签和表格各有明确语义；图标按钮有可访问名称，装饰与有效图片分别处理。
- 检查键盘到达、可见焦点、顺序、遮挡和弹层退出/焦点恢复。原生控件已有的键盘行为应保留，不重复强加事件。
- 表单支持名称、输入类型、自动填充和有效标签，失败信息靠近字段并有可行下一步；粘贴与缩放不被无故禁用。
- 异步进展与错误更新有适合的可感知反馈，不能只靠颜色、鼠标悬停或动画说明状态。
- 核对长文本、空数据、不同数字/日期区域、窄屏和触摸状态；破坏性动作采用与产品风险一致的确认或恢复方式。
- 减少运动偏好、动画停止/中断和媒体替代内容应可用；具体标准和控件模式需要时核对W3C正式资料。
- 性能建议依据实际测量：大量列表、布局反复读写、字体/图片跳动等；列表数量与样式口号不是万能阈值。
- 英文大小写、字体和文案服从项目规范；不要为符合上游个人风格破坏既有产品一致性。
- 固定规则仅是审查依据，不证明法规符合或辅助技术实际可用；缺少浏览器/读屏环境时明确未验证项。

## 回写与证据
组件状态和修复约束写 `/完整细节`，验证场景写 `/测试责任矩阵`，发现/截图/真实操作结果写 `/验证证据`。
静态语义审查属于 review；真实键盘、浏览器或辅助技术操作才可登记对应 execution。
只处理任务范围内实际问题，不要求每次联网重取规范或全站重设计。
