# 接口与配置误用审查

安全相关接口、配置、鉴权或加密边界存在可影响行为的选项时使用；普通业务正确性仍由对应模块审查负责。
输入：接口/配置契约、实际默认值、调用示例、边界数据与兼容约束。
产出：可复现的误用路径、影响、改进方案与迁移代价，允许有依据的零发现。

## 检查容易走错的路径
- 定位调用方可选择的算法、模式、超时、次数、密钥、权限和绕过选项，区分项目真实需求与多余自由度。
- 明确零、负数、空字符串、null和缺失字段的语义，检查它们是否意外关闭校验、无限等待或使错误变成成功。
- 对参数同类型但不同语义的接口检查交换、复用和误传风险；可用语义类型、校验或高层接口降低误用。
- 配置不仅单项有效，还要检查组合、环境覆盖、拼写错误和构造器传值；未知值不应静默落到安全绕过路径。
- 追踪失败返回、异常和空结果是否被调用方观察；不能把记录日志或文档警告当作已阻止不安全使用。
- 分别检验恶意输入、复制示例和误解语义三类场景，给出路径与现有防护，不凭“参数看起来危险”断言漏洞。
- 优先让常用合法路径可靠、安全并易理解；保留必要兼容时写清迁移、回滚和不能立刻改变的约束。
- 具体语言/密码库资料仅在事实匹配时读取；历史案例不是当前版本的漏洞证明，实时技术事实需核对官方文档。

## 回写与证据
接口语义、默认值和边界写 `/完整细节`，场景写 `/测试责任矩阵`，具体发现与证据写 `/验证证据`。
检查计划与模型判断是 review，真实探针结果才是 execution。探针只在允许范围或隔离副本运行，不能自动修改生产配置。
需要范围外迁移时提出具体方案，不因上游口号擅自破坏兼容或抢占主流程。
