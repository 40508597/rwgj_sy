# UI视觉与交互设计

当前任务实际包含界面、组件、移动/桌面交互或明确的视觉改造时使用；视觉意图可以跨平台，实现方法服从实际工具。
输入：受众、界面主要任务、内容、已有设计系统、交互状态和平台约束。
产出：有理由的视觉方向、可实现的组件/状态规则与验收依据。

## 有目的的界面设计
- 从真实主题、受众与单一主要任务确定视觉语言；缺少次要内容可作合理假设，关键产品事实缺失要明确保留。
- 先识别现有tokens、组件、字体与品牌规则；改造时解释保留或改变的理由，不为新鲜感重建整套系统。
- 形成可辨识的字体、色彩、布局、留白和层次关系；用真实内容检验长短文本、数字、空状态和重要操作。
- 视觉选择服务信息与操作，装饰不得遮蔽可读性、键盘焦点、错误反馈或性能目标。
- 对交互补齐处理中、成功、失败、不可用、空结果和恢复条件；导航、保存和取消应与项目状态模型一致。
- 动效目的与可中断性明确，照顾减少运动偏好；不要把大型背景效果视为所有产品的必需项。
- 根据实际平台重排小屏、触摸与键盘操作；上游Web代码范例不会把原生界面改成Web技术栈。
- 宿主已有frontend-design、ui-ux-pro-max、design-system时按元数据选最匹配者；工具或数据缺失记录实际限制。

## 回写与证据
界面与组件归属写 `/页面拓扑`，事件和状态写 `/完整细节`，资源与实现责任写 `/实现清单`。
设计说明属于 review；实际渲染、截图或交互证据进入 `/验证证据`，验收责任归 `/测试责任矩阵`。
没有真实渲染不能声称截图验收或视觉效果已验证；实际平台工具存在时按授权范围运行。
