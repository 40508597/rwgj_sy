# Web浏览器验收

真实Web应用需要操作验收、且宿主具备适用浏览器工具时使用；无运行工具时保留计划和未验证项。
输入：当前应用地址/运行方式、验收场景、可用浏览器工具、测试数据及允许的读写范围。
产出：真实操作步骤、实际结果、截图/日志和未覆盖场景，区分界面观察与业务后端证据。

## 先观察再操作
- 先确认页面和服务实际就绪，读取当前DOM/界面状态，再从可见内容确定稳定的名称、角色或标识。
- 等待具体可观察条件并设合理超时；长连接和后台请求不等于页面未就绪，不统一要求networkidle或固定睡眠。
- 根据当前界面操作，核对操作前后真实状态与反馈；验证请求成功、空结果、失败、重试和恢复的适用路径。
- 优先语义定位和用户可观察断言，避免猜选择器或把截图存在当作功能正确；动态内容要固定或说明比较条件。
- 采集必要的控制台/网络/服务证据，识别界面显示成功但后端失败、状态丢失或刷新后不一致的情况。
- 对静态页面、已运行应用和需要启动的应用分别选择现有项目命令；不执行未审查的上游辅助脚本。
- 工具可以是宿主浏览器、项目现有Playwright或其他实际可用工具；不强制Python、Chromium或安装新运行时。
- 测试使用隔离/指定数据，修改范围服从用户授权与项目约束；发现范围外真实操作需先形成可审查方案。
- 保存有定位价值的证据及当前输入/应用版本。运行环境不可用、场景未跑或只做静态阅读都如实报告。

## 回写与证据
场景与责任写 `/测试责任矩阵`，实际操作、截图/日志、失败和未验证项写 `/验证证据`。
验收设计属于 review，真实运行对应 execution；CLI执行需要当前输入的收据，宿主UI操作保留实际工具输出与证据。
本入口不证明原生桌面UI、所有浏览器或所有用户设备已验证，也不自动发布、推送或发送消息。
