# 通用 CLI Agent 适配说明

通用 CLI Agent、Cursor、Windsurf、Cline、Continue 或自研编程智能体若没有专用适配文档，默认使用本说明。

最低执行要求：

1. 读取 `SKILL.md`。
2. 检查当前项目是否存在 `architecture.json`。
3. 若存在，任何代码、接口、数据、测试、文件或行为修改都先更新 `architecture/index.json` 或相关架构切片。
4. 用标准输出契约模拟模块智能体。
5. 可运行脚本时运行校验；不可运行时记录降级原因。
6. 最终更新验证证据、上下文恢复点和变更记录。

若智能体无法编辑文件，只能输出变更计划，不得声称已完成实现。

## 收尾门禁（C 档：一句话契约，极小注意力）

平台不支持 Stop hook（多数通用 CLI Agent）时，用一句话契约兜底。这是**唯一**需要进入模型注意力的门禁规则，刻意压到一行，避免重新堆叠流程负担：

> 声明受管项目完整交付前，必须运行 `python "<gate_check_path>" "<项目根>" --quality-required --json`；退出码非 0 时如实汇报未通过项，并把失败项写入上下文恢复点与变更记录。`<gate_check_path>` 是技能安装目录内 resolve_tool.py 对 gate_check 返回的 JSON.path（完整脚本绝对路径），不得再追加脚本名；启动、查看等局部任务只报告本次结果。

**完成宣告契约**：通过后结论首行固定为「【任务完成】」；未通过时首行固定为「【未通过验证】」。该首行格式供宿主侧自动化门禁确定性检测（避免关键词猜测），模型不得使用其他首行措辞宣告收尾结论。

- 脚本统一检查核心占位符、必需阶段、阻塞项、架构合规、代码漂移、流程脱轨和本次必需质量规则。按 `../references/universal-quality.md` 在调用方项目配置事实和规则；缺配置、缺证据或过期证据为未验证。语义质量与测试充分性仍需工程判断。
- `gate_check.py` 退出码：`0=PASS`、`1=FAIL`、`2=无法判定`。1 和 2 均不得声明验证通过；非受管任务不适用此门禁。
- 本文件是执行约定，未安装并验证宿主适配器时不提供自动拦截。不得把固定首行或文档配置示例描述为已经启用的保护。
- 能挂平台 hook 的环境优先用 A 档（见 `claude.md`）——hook 不进模型上下文，零注意力，比一句话契约更彻底。

## 专业能力按需接入

按 `../references/capability-index.md` 用宿主已经给出的技能元数据和当前需求/模块/风险/姿态筛选，规划后实际读取所选文件；没有提示注入API时就是载入当前上下文。无宿主元数据时使用已知可用本地参考，不自动安装或全量读取。启用调用后留最小计划/使用证据并核验回写；缺必需能力或执行证据为unknown，小任务不强迫完整语境，完全跳过不建状态。
