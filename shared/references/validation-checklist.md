# 关键规则

> 原 `hard-gates.md`（硬约束门禁）已合并入本文末「硬约束门禁」一节；旧记录中指向
> hard-gates.md 的引用以本文件为准。

### 先判定，再行动

范围判定、一次简短回执、状态读取与降级以 [LAYER](../../skills/task-architecture/LAYER.md) 为准。未完成本次判定前，不创建业务文件、修改代码或扩展范围；续轮不重复打印未变化判断。

### 受管项目必须自动接管

当前项目存在有效架构入口时，代码、UI、接口、数据、测试、文件或行为修改遵循架构先行：先核对相关模块架构或集中切片，设计与归属变化时先更新所属事实；已登记设计内的实现沿用现有契约，保留实际变更与验证记录。用户没有显式输入 `/修改架构` 不改变此约定。

如果用户明确要求跳过架构更新，服从本次范围，说明实际未同步事项及漂移影响；最终汇报和已有变更记录据实标明，不能把未更新描述为已一致。

### 接口即合同

模块的"导出"是对下游的承诺。修改导出接口时沿实际消费者与依赖链确认影响，必要时继续扩展；需要适配或重新验证的模块回到相应未完成状态，不把未受影响模块一律重置为"计划中"。

### 变更记录不可省略

每次修改架构切片必须在变更记录中追加：时间、操作类型、原因、影响范围。局部 Bug 也保留本次变化与验证依据；已有详细证据用路径引用，不重复全文。

### 修改后一致性自动校验

**每个相关变更批次完成后执行适用的 21 项检查，校验结果写入变更记录；同一批次不要求每次写文件都重跑。脚本检查结构和部分一致性，接口语义、异常覆盖等仍需工程验证，不能把脚本退出码 0 等同于全部语义已通过。**

```
校验1：依赖完整性
  遍历所有模块的 依赖.使用接口 → 检查目标模块的 导出 中是否存在该接口
  → 不存在 = 悬空依赖，必须修复

校验2：路由-页面对应
  遍历入口路由中所有路径 → 检查是否有对应的页面拓扑节点
  → 缺失 = 路由指向空白页

校验3：接口-实现对应
  遍历接口契约中所有导出接口 → 检查实现清单中是否有对应的文件
  → 缺失 = 接口只有声明没有实现

校验4：数据表-迁移对应
  遍历数据拓扑中所有表 → 检查是否有迁移脚本路径
  → 缺失 = 表无法创建

校验5：需登录页面-认证依赖
  遍历入口路由中标记"需登录"的路径 → 检查对应页面是否依赖了认证模块
  → 缺失 = 页面缺少认证保护

校验6：测试覆盖异常
  遍历接口契约中每个接口的 可能异常 → 检查完整细节中测试用例是否覆盖了每个异常
  → 缺失 = 异常路径无测试覆盖

校验7：依赖图无环
  从模块拓扑的依赖图检测是否存在循环依赖
  → 存在 = 架构错误，必须重构

校验8：交互完整性
  遍历本次涉及的所有组件/接口/命令
  → 检查是否有交互完整性检查记录
  → 检查是否有未通过的检查项（不含"不适用"）
  → 有未通过项 = 设计不完整，必须补全

校验9：代码漂移
  遍历本次新增/修改的文件、接口、路由、命令、数据结构
  → 检查是否都可追踪到拥有事实的根/模块架构或既有登记切片
  → 代码有、架构无 = 漂移，必须先补架构切片

校验10：变更可追踪
  检查本次变更是否写入变更记录，且包含原因、影响范围、验证结果、剩余风险
  → 缺失 = 黑盒变更，必须补记录

校验11：入口类型清晰
  遍历入口结构
  → 必须按 用户入口、接口入口、命令入口、事件入口、系统入口、资源入口 分开登记
  → 不得新增 页面路由/API路由/静态资源路由/CLI命令树/后台任务/桌面窗口/桌面菜单栏/托盘入口/本地协议/文件关联/系统通知 等入口主键
  → 混用入口主键 = 校验规则会误判，必须拆分到通用入口类型

校验12：异常契约测试
  遍历接口契约中每个接口的 可能异常
  → 检查完整细节或测试责任矩阵中是否有对应测试场景
  → 无法真实触发时，必须说明 mock/monkeypatch/替身注入方式
  → 缺失 = 契约假闭环，必须补测试或补说明

校验13：验证证据完整
  检查本次完成项是否记录自动化测试、架构校验、浏览器验收、截图、手动检查或未验证项
  → 只写"已验证"但无证据 = 追踪不足，必须补验证证据

校验14：上下文恢复点完整
  检查根当前事实或明确登记任务记录的恢复点；核心字段按schema，未验证项与风险可引用权威证据。集中布局按实际任务切片读取，不额外新建双源
  → 缺失 = 压缩/中断后无法可靠续跑，必须补上下文恢复点

校验15：功能树落位完整
  按 [候选状态与本轮实施范围](function-clusters.md#候选状态与本轮实施范围) 判定本轮纳入或已有实施证据的叶子节点
  → 检查是否记录验收标准、异常路径、架构落位、验证责任
  → 架构落位至少要指向模块，并按实际形态指向入口/接口/数据/文件/测试
  → 涉及运行形态、交付物或系统集成的功能必须同时指向对应入口、交付物或系统集成节点
  → 缺失 = 纳入功能只停留在需求清单，必须补落位；尚未实施候选记录合法取舍和理由，免当前实施细节但仍检查范围/结构一致性；既有实现不能只改状态免检

校验16：专业能力索引边界
  检查专业能力索引是否只记录能力类型、触发信号、调用建议、回写位置和边界
  → 不得把外部技能写成强制依赖，不得让专业能力索引接管任务流程
  → 若本次调用了 UI/测试/安全/性能/桌面端/可执行交付/部署/文档等专业能力，检查产出是否回写到拥有相应事实的根/模块架构或既有登记切片
  → 缺失 = 专业能力游离在真相源之外，必须补回写位置或删除越权内容
  → 启用专业调用计划时运行 check_capability_usage.py：核对当前计划/语境、实际使用、读写范围、产物与JSON Pointer回写；review与execution分开，缺必需执行收据为unknown
  → 旧索引没有实际调用时可跳过专项，不能将skipped写成专业能力已通过

校验17：UI设计与图标库质量
  遍历功能树、页面拓扑和完整细节中涉及页面/组件/仪表盘/管理后台/编辑器/移动端/桌面端界面的节点
  → 检查是否记录设计系统或视觉方向、组件状态、响应式责任、图标库/图标语义、截图或浏览器验收责任
  → 如果项目已有图标库，检查是否优先使用已有图标库；没有图标库时，必须说明选择、暂不引入或待用户确认
  → 缺失 = UI 只停留在可用层面，必须补设计感、图标系统和验收责任；不得声称 UI 已完成

校验18：受管项目架构先行
  检查当前项目是否存在根架构 `architecture.json` 或 `architecture/` 辅助目录，核对实际入口与登记模块
  → 若存在，检查本次代码/UI/接口/数据/测试/文件/行为修改之前是否已更新所属权威事实；已覆盖的局部实现补本次变更、测试与影响记录
  → 若未先更新架构切片，必须标记为流程违规，补写架构变更、影响范围、验证证据和变更记录
  → 若用户明确要求跳过架构文件夹，必须记录跳过原因和代码漂移风险

校验19：模块详情完整
  遍历模块拓扑中的每个模块节点
  → 检查模块详情中是否存在对应模块编号
  → 至少记录职责、非职责、所属功能树节点、上游依赖/下游消费者、内部结构、数据读写责任、错误边界、配置项、安全边界、测试责任
  → 无状态/无配置/无性能要求的模块必须明确写“不适用”，不得留空
  → 缺失 = 模块边界不清，容易职责漂移，必须补模块详情后再实现或修改代码

校验20：模块树层级完整
  递归布局先核对模块路由及派生包含树；模块树缺失/为空时由路由合成，显式非空模块树保留补充分组
  → 核对编号、父子关系、职责与落位；不在每份模块架构重复维护全局树
  → 子模块的父模块必须指向真实存在的父节点；根模块父模块写 null 或“不适用”
  → 模块树不得出现父子循环；跨分支依赖在权威关系事实声明，由工具按来源合成；不得藏在子模块关系里或要求多处复制同一边
  → 已确认或进行中的叶子模块必须在模块详情、实现清单、测试责任矩阵中有对应记录，或明确标为“待设计/待实现/延期”
  → 缺失 = 模块包含或职责边界不清，先补实际路由/关系与相关模块语义再实现

校验21：物理架构与登记同步
  若根架构启用 模块路由：
  → 逐层检查子模块路径、唯一编号、父子职责和实际后代目录；包含树与依赖图分开
  → 各模块只有本模块事实所有权，实现清单不得侵入子模块；根层可以拥有自己的实现
  → 全量检查未登记模块架构、失效路由与缺失实现；局部read成功不代表全项目通过
  → 协议与命令见 recursive-modules.md；派生模块目录只能由工具生成
  若 架构切片.启用 为 true：
  → 检查是否存在 architecture/ 架构文件夹和 architecture/index.json 总索引
  → 检查总索引是否包含架构模式、根入口文件、切片目录、切片清单、同步规则
  → 切片清单中的路径必须位于 architecture/ 文件夹内，真实存在，类型必须清晰，状态和更新时间必须存在
  → 修改切片时，总索引必须同步更新时间、切片状态和变更记录摘要
  → 跨切片依赖在指定权威关系记录中声明，工具合成全局图；总索引不重复维护完整关系
  → 总索引与切片冲突时必须走 /校验架构 分类，不得直接覆盖
  → 缺失 = 切片真相源分裂，必须先同步总索引和切片再继续
```

### 禁止事项

以下检查先按已锁定需求判断适用性。质量责任可以由现有模块承担；模块数量和是否有独立配置、日志或数据库模块，不是完成质量的判据。没有相关需求的项目应记录不适用理由，不得据此追加产品能力。

- 存在可变部署参数，却把地址或凭据硬编码，缺少适用的配置入口。
- 存在失败路径，却没有明确的错误边界、返回约定或用户反馈。
- 需要运行排障或审计，却没有与运行形态相符的诊断证据；小型 CLI 的标准错误输出可承担适用责任。
- 接受外部输入，却没有按契约校验非法值和边界值。
- 使用持久化数据库且本次改变其结构，却没有可验证的迁移与失败恢复方案。
- 存在边界或错误路径，却只有正常路径测试。
- 声明的模块依赖图存在未经允许的循环。
- 接口存在可发生的异常，却只定义成功返回。

### 精细化程度标准

**唯一判断标准：一个不熟悉项目的开发者，拿到 `architecture/` 架构文件夹后，能否独立写出完整的可运行代码？** 能→够了。不能→继续细化。

## 硬约束门禁

硬约束门禁约束当前动作的前置条件。设计补齐期间按相应阶段检查结构底线，修改代码前检查架构落位和接口影响；`judge_progress.py` 与 `gate_check.py` 用于最终完成声明。不得要求最终完成裁判先通过，才允许开始实现或补齐尚未完成的设计。

### 门禁结果

```json
{
  "门禁名称": "",
  "结论": "通过 | 不通过 | 阻塞 | 需要确认 | 降级执行",
  "阻塞项": [],
  "必须修复": [],
  "允许进入阶段": "",
  "禁止进入阶段": "",
  "证据": []
}
```

### 必备门禁

| 门禁 | 通过条件 | 未通过处理 |
|---|---|---|
| 占位符门禁 🆕 | 核心字段无 `__待填__` 占位符（运行 `check_placeholders.py` 返回 0）| 不得声明完成，必须填写核心占位符 |
| 进度状态门禁 🆕 | 所有必需阶段已完成（`manage_state.py show` 显示必需阶段 9/9 = 100%）| 不得声明完成，必须完成所有必需阶段 |
| 需求落位门禁 | 本次任务能追溯到所属根/模块架构或既有切片中的功能、验收、模块边界或非目标 | 中止并补充架构落位或询问用户 |
| 架构先行门禁 | 受管项目已先更新实际变化的权威事实或已覆盖实现的本次变更/测试/影响记录 | 不得修改代码，先补架构文件夹 |
| 模块边界门禁 | 新增/修改文件已落到模块树、模块详情和实现清单 | 不得创建或修改未登记文件 |
| 接口契约门禁 | 跨模块调用已登记接口和下游影响 | 不得跨模块直接调用 |
| 功能族裁决门禁 | 功能族候选已分类并裁决纳入/待确认/排除 | 不得把候选直接实现 |
| 风险确认门禁 | 高风险、不可逆、生产、权限、支付、迁移已确认 | 进入阻塞或需要确认 |
| 验证证据门禁 | 完成项有命令、截图、手检或未验证项记录 | 不得声明已完成 |
| 平台降级门禁 | 平台缺能力时已记录降级原因和替代验证 | 不得假装已运行工具 |

### 新增门禁说明（F+B+C 强制执行机制）

**占位符门禁**：
- 检查命令：`python shared/scripts/check_placeholders.py architecture.json`
- 分级：核心字段（项目名称、功能树、模块详情等）必须填写
- 强制点：LAYER.md 三重校验第1步，完成前自检硬性要求

**进度状态门禁**：
- 检查命令：`python shared/scripts/manage_state.py show`
- 必需阶段：需求理解、功能树、模块树、模块详情、入口定义、数据拓扑、实现清单、测试责任、验证证据（9 个，含验证证据）
- 可选阶段：接口契约（跨模块调用业务才需要，无则跳过记 skipped）
- 强制点：LAYER.md 第一动作，每完成一个阶段更新

### 统一完成裁决

`judge_progress.py` 与 `gate_check.py` 共用占位符、必需阶段、阻塞项和架构判定；收尾门禁另查漂移、脱轨、质量红线和启用的专业能力使用记录。完整交付按 `universal-quality.md` 配置本次必需质量规则，运行 `gate_check --quality-required`；规则、事实或当前证据缺失为未验证。0=通过，1=明确失败，2=检查缺失、损坏或不可用。只有0证明选定自动检查通过，语义审查、实际行为与覆盖充分性仍按各自证据说明。状态计数从阶段清单重算；重要字段警告和未登记文件仍保留原有提示策略，需人工判断与回写。

### 退出要求

最终说明本次门禁结果、降级与未验证边界；未满足完成定义时只报告已完成设计/实现和未完成验证。详细失败记录唯一维护，恢复点与变更记录保存必要结论和引用，不再全文复制。
