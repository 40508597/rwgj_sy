# 五个命令速查卡

## 未写命令时

用户只说“使用任务架构”“按这个技能”“按架构来”，但没有写具体命令时，必须自动判定：

| 场景 | 自动选择 |
|------|------|
| 检查一致性、找漂移、评估现状 | `/校验架构` |
| 已有代码纳入管理 | `/分析架构` |
| 新项目从零开始 | `/创建架构` |
| 新增架构文件夹中不存在的功能/模块/页面/接口 | `/追加架构` |
| 修改已有功能、修 Bug、删 UI、改字段、优化已有模块 | `/修改架构` |

第一段汇报写明“自动判定命令”，不得因为用户没写命令就跳过架构文件夹。

## /分析架构 — 代码 → 架构文件夹

**输入**：已有项目目录
**输出**：根指针 `architecture.json` + `architecture/` 架构文件夹
**适用**：已有项目想纳入架构管理

关键步骤：
1. 扫描目录结构 → 识别模块边界
2. 分析 import 关系 → 确定依赖
3. 提取函数/类签名 → 定义接口
4. 生成现状画像 → 只记录代码真实存在什么
5. 生成治理建议 → 标出缺失的功能簇、商业标配和架构风险
6. 生成架构文件夹 → 汇报确认

---

## /创建架构 — 需求 → 架构文件夹

**输入**：需求描述（文字）
**输出**：根指针 `architecture.json` + `architecture/index.json` + 相关切片
**适用**：新项目从零开始

关键步骤：
1. 需求语义展开 → 模糊需求变成功能域
2. 功能本体展开 → 展开天然绑定功能、状态、交互、异常
3. 功能树建模 → 递归拆到可验收、可落位、可测试的叶子节点
4. 专业能力索引匹配 → 判断是否需要 UI/测试/安全/性能/客户端/可执行交付/部署/文档等已有技能辅助
5. 架构落位展开 → 落到模块、运行形态、入口、接口、数据、页面/界面、交付物、系统集成、测试
6. 模块树展开 → 定义父模块、子模块、叶子模块和落位关系
7. 模块详情展开 → 定义职责、非职责、内部结构、数据读写、错误边界和测试责任
8. 确定依赖拓扑 → 分配优先级
9. 生成架构文件夹 → 展示模块树和依赖图确认

---

## /修改架构 — 需求变更 → 更新架构文件夹

**输入**：变更需求 + 现有根指针和 `architecture/` 架构文件夹
**输出**：更新后的 `architecture/index.json` 或相关切片
**适用**：需求变化，模块接口或文件需调整

关键步骤：
1. 定位受影响模块
2. 追踪依赖链（谁依赖了被修改的模块）
3. 按变更类型矩阵确认必须更新的架构切片
4. 更新接口定义 + 重置受影响模块状态
5. 输出架构切片修改前后对比
6. 追加变更记录和上下文恢复点

---

## /追加架构 — 新模块 → 更新架构文件夹

**输入**：新模块需求 + 现有根指针和 `architecture/` 架构文件夹
**输出**：追加了新模块的 `architecture/index.json` 或相关切片
**适用**：项目扩展，新增功能模块

关键步骤：
1. 确定新模块的依赖（精确到使用哪个接口）
2. 更新功能树（确认新增功能属于哪个功能域/功能组，叶子节点如何验收）
3. 更新专业能力索引（确认是否需要专业技能辅助，以及产出回写位置）
4. 更新模块树（确认挂到哪个父模块；必要时拆出子模块）
5. 定义模块详情（职责、非职责、上下游、内部结构、数据读写、错误边界、安全和测试责任）
6. 确定优先级（排在所有依赖之后）
7. 定义新模块的接口和文件
8. 输出架构切片修改前后对比
9. 追加到架构文件夹 + 变更记录和上下文恢复点

---

## /校验架构 — 架构文件夹 ↔ 代码

**输入**：现有根指针、`architecture/` 架构文件夹 + 项目代码
**输出**：一致性报告
**适用**：检查项目是否出现代码漂移、架构过期、契约不一致或测试缺失

关键步骤：
1. 读取 `architecture/index.json` 和相关切片的四层结构
2. 对照代码目录、入口类型、接口、数据结构、测试文件、验证证据
3. 标记架构有代码无、代码有架构无、契约不一致、测试缺失、入口混用、证据缺失
4. 对偏差分类：架构漏登记、代码越界、架构设计过期、需求不清
5. 输出总体结论、偏差清单、影响范围和修复建议
6. 用户要求修复时，先补架构切片，再按 `/修改架构` 或 `/追加架构` 改代码

## 完成前

对照 `references/execution-templates.md` 的完成定义：
- 架构先行
- 代码与架构文件夹一致
- 验证证据已记录
- 上下文恢复点已更新
- 变更记录已追加
- 剩余风险已说明
