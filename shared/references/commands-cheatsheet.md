# 五个命令速查卡

给人看的快速路由卡。每个命令的详细流程、边界与安全修改模式见 `references/commands-workflows.md`，本文不重复步骤清单。

## 未写命令时

用户只说"使用任务架构""按这个技能""按架构来"，但没有写具体命令时，必须自动判定：

| 场景 | 自动选择 |
|------|------|
| 检查一致性、找漂移、评估现状 | `/校验架构` |
| 已有代码纳入管理 | `/分析架构` |
| 新项目从零开始 | `/创建架构` |
| 新增架构文件夹中不存在的功能/模块/页面/接口 | `/追加架构` |
| 修改已有功能、修 Bug、删 UI、改字段、优化已有模块 | `/修改架构` |

第一段汇报写明"自动判定命令"，不得因为用户没写命令就跳过架构文件夹。

## 五个命令一句话

| 命令 | 输入 → 输出 | 适用 |
|------|-------------|------|
| `/分析架构` | 已有项目目录 → 根指针 `architecture.json` + `architecture/` 架构文件夹 | 已有项目想纳入架构管理（先现状画像，再治理建议） |
| `/创建架构` | 需求描述 → `architecture/index.json` + 相关切片 | 新项目从零开始（功能簇 → 功能树 → 模块树 → 逐块设计） |
| `/修改架构` | 变更需求 + 架构文件夹 → 更新后的索引/切片 | 需求变化，已有模块接口或文件需调整（先影响范围分析） |
| `/追加架构` | 新模块需求 + 架构文件夹 → 追加新模块的索引/切片 | 新增架构文件夹中不存在的功能/模块 |
| `/校验架构` | 架构文件夹 + 项目代码 → 一致性报告 | 检查漂移、架构过期、契约不一致、测试缺失 |

## 完成前

对照 `references/execution-templates.md` 的完成定义：
- 架构先行
- 代码与架构文件夹一致
- 验证证据已记录
- 上下文恢复点已更新
- 变更记录已追加
- 剩余风险已说明
