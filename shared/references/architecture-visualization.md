# 项目架构可视化

用于用户要求架构图、完整项目画布、设计评审或长程任务中的可视化阅读时。先登记本次相关架构，再按需生成；小修改不要求每次重新铺开全项目。项目逐步完善时，同一画布继续承载功能、模块、接口、数据、页面、任务、实现、验证与专项资料，不把最低交付条件当作信息上限。

本次仅从已有真相源生成图纸时，走只读派生路径：已有进度状态可读取展示，不初始化或推进阶段，也不要求重新执行设计、实现流程。生成阅读产物本身不算业务或架构修改；分类工具仅因“架构”等关键词建议完整流程时，以实际是否修改真相源或业务为准。用户同时要求新增设计、修改架构或实现功能时，照常执行对应主流程，再按需渲染。

## 生成

保持工作目录为调用方项目。先从本次加载的 `SKILL.md` 定位技能安装目录，再分别解析工具；使用返回 JSON 中的完整 `path` 执行，不追加脚本名：

```bash
python "<技能安装目录>/shared/scripts/resolve_tool.py" render_architecture --json
python "<render_architecture_path>" architecture.json --format html --output "<产物绝对路径>/项目架构.html"
```

`<render_architecture_path>` 替换为已解析的绝对脚本路径；输出位于调用方项目或用户指定产物目录，不写入全局技能目录，也不覆盖输入索引、切片或进度状态。根 `architecture.json` 可包含递归模块路由，也可作为集中布局的入口指针。解析规则见 [任务架构入口](../../skills/xl-ai-language/LAYER.md)，工具见 [render_architecture.py](../scripts/render_architecture.py)。

| 需求 | 参数 |
| --- | --- |
| 完整项目渐进画布 | `--format html`（默认 `--html-view project`） |
| 专题图表报告 | `--format html --html-view report` |
| Mermaid Markdown 报告 | `--format md`（默认输出格式） |
| 供其他工具消费的结构化报告 | `--format json` |

`--max-nodes` 控制报告分图密度，不截断项目画布的数据。缺失或错误输入按工具错误处理，不凭文件生成成功宣布内容或验证已通过。

依赖引用歧义等可读取的声明错误不会阻止生成阅读产物。Markdown 与专题 HTML 保留渲染提示，列出诊断代码、实际文件、JSON Pointer 与来源 SHA256；JSON／专题 HTML 载荷另含 `依赖诊断` 和 `依赖提取`。`incomplete` 表示存在未形成明确依赖边的声明，零条已解析边不等于项目没有依赖；`complete` 只表示已加载声明的解析未发现阻断诊断，不代表源码依赖完整、架构校验或测试通过。说明性记录保留提示但不作为依赖边；纯内存调用没有物理出处时明确标注缺少来源，不猜文件或哈希。全部原始字段仍保留在完整架构资料中。

## 阅读完整项目

- 从总览选择对象，逐层展开到原字段与完整正文；未知字段、原文件补充资料、空容器也保留。折叠摘要和缩略聚合只改变显示密度，不删除底层内容。
- 搜索名称、编号、JSON 路径或原值；正文命中会展开并定位。先局部阅读，按需要展开当前分支的下一层，或批量铺开全项目。
- 查看关系的类型、方向和声明位置；需要核对字段时查看物理文件、JSON Pointer 与 SHA256，并定位原声明。阅读分组或重复引用不是新的业务对象，覆盖统计也不等于测试通过。
- 使用“只看所选分支”聚焦当前对象；搜索仍覆盖全项目，“显示全项目”与返回保留分支展开。缩略导航对应当前视野；引用面包屑保持当前关系位置。
- 使用总览、缩略导航、局部定位与返回在全景和细节之间移动；总览保留已有展开。Alt + 方向键选择父、子或相邻节点，Home 返回总览；方向键平移。长正文通过平移继续阅读，不以屏幕当前可见节点数判断信息是否完整。
- 浏览器保存展开、搜索与视角，阅读状态可独立导出、导入。状态属于阅读器，不回写 `architecture/_state.json`，也不替代项目恢复点或验证证据。

## 更新与事实边界

### 只读核验已生成图纸

生成后，HTML 始终显示“生成快照、尚未核验当前输入”，并提供来源与生成依据；浏览器只展示内嵌资料，不读取任意本地文件、不自动执行命令。用已有本地入口核验当前项目输入：

```bash
python "<render_architecture_path>" architecture.json --check-view "<产物绝对路径>/项目架构.html"
```

该命令仅输出 JSON，不修改图纸、架构或进度状态。`freshness=fresh`／`status=pass`／退出码 `0` 表示当前入口身份、输入文件集合、存在状态、严格 SHA256 与产物内容一致；`stale`／`fail`／退出码 `1` 表示已观察到变化；`unknown`／`unknown`／退出码 `2` 表示缺少有效清单、清单损坏或当前完整依据尚未读全。输出的 `generated_basis` 是生成依据，`current_basis` 是本次读取依据，`changes` 列出差异；任何状态都不证明架构质量、实现正确或测试通过。旧图没有清单时保持未知，重新生成后再核验。

生成清单内嵌于项目 HTML、专题 HTML、Markdown 和 JSON，不另建图种或服务器。HTML／Markdown 产物指纹按原始 UTF-8 字节核验（包括换行）；JSON 产物指纹按严格解析后的规范语义核验，空白变化不改变该指纹。清单包含：实际加载的入口／指针／集中切片／递归模块架构、选定状态文件（即使尚不存在）、schema、两份 HTML 模板，以及渲染脚本、`_archlib`、`_architecture_core`、`_module_tree`、`_architecture_visual`、`manage_state`、`check_quality_redlines`、`check_project_quality` 的文件字节；质量标注涉及的红线复核文件、登记的实现文件与复核证据也纳入。缺失候选文件用 `exists=false`／`sha256=null` 记录，因此后来新建状态或复核输入也会使旧图过期。未登记源码、仓库的其他文件、浏览器阅读状态与浏览器环境不属于该清单。

核验重新从本次提供的入口发现输入集合，严格检查清单版本、字段、唯一绝对路径、有限 JSON 与小写 64 位 SHA256，不以清单遗漏或损坏作为通过依据；清单与视图中的脚本、命令或来源资料只作为数据解析。文件删除、登记集合变化、入口切换或产物正文变化都不会继续报告 `fresh`。SHA256 用于一致性对比，不是签名或作者认证；有人同时重写正文和清单时，核验不替代可信来源确认。

如果生成时用了显式状态路径，核验时保留同一参数；核验不让图纸自行指定本地输入路径：

```bash
python "<render_architecture_path>" architecture.json --format html --state-path "<项目绝对路径>/状态.json" --output "<产物绝对路径>/项目架构.html"
python "<render_architecture_path>" architecture.json --state-path "<项目绝对路径>/状态.json" --check-view "<产物绝对路径>/项目架构.html"
```

输入改变后按原生成命令重新生成，再运行 `--check-view`；项目 HTML 仍是默认模式，专题报告仍用 `--html-view report`。生成失败保留既有图纸和原始输入，写入成功时一次替换完整单文件；核验不接受 `--output`，也不会反向编辑架构或自动重新生成。

项目总架构与登记的模块架构（或集中布局中的索引与切片）是架构事实源，HTML 是输入快照的派生视图。按已有架构工作流修改并校验后重新生成；通过仍存在的稳定标识恢复阅读位置。数组记录使用明确且集合内唯一的 `编号`、`id` 或 `ID`，编号类型与所在集合参与身份；缺少稳定编号的记录仅按原位置和原内容校验恢复。已删除、歧义、内容变化或无法对应的项跳过并提示数量，不凭名称或下标推断身份。对比或评审时核对来源与哈希，不能把旧视图当作当前事实。

该功能不限制项目语言、框架、文件后缀或 IDE。完整保留已登记内容，明确关系才绘制语义连线；未解析引用和歧义保留提示，不从名称或邻近位置猜依赖。需要未登记的源码调用链、代码质量或真实执行结果时，先使用相应采集与验证流程记录事实，再重新渲染。

架构声明、进度描述和已有证据文本不证明当前实测通过。质量判定仍按 [通用质量协议](universal-quality.md)；视图不得反向编辑真相源或自动执行来源代码。
