# 智能体标准化输出契约

所有虚拟或真实智能体输出都必须可合并、可校验、可恢复。输出可以嵌入 Markdown，但核心内容应保持 JSON 可解析结构。

## 标准结构

```json
{
  "输出类型": "模块提案 | 接口提案 | 风险报告 | 验证报告 | 阻塞报告 | 门禁结果",
  "关联语境": "ctx_001",
  "负责范围": {
    "模块": [],
    "功能树节点": [],
    "接口": [],
    "文件": []
  },
  "结论": "通过 | 不通过 | 需要确认 | 阻塞 | 降级执行",
  "功能族展开": {
    "核心功能": [],
    "天然绑定功能": [],
    "商业标配功能": [],
    "待确认扩展": [],
    "跨模块提案": [],
    "明确排除": []
  },
  "变更提案": [],
  "接口影响": [],
  "风险": [],
  "必须同步": [],
  "验证责任": [],
  "证据": [],
  "未验证项": [],
  "下一步": []
}
```

## 输出要求

- `输出类型` 和 `结论` 必填。
- 任何 `跨模块提案` 必须进入 `接口影响` 或 `必须同步`。
- `需要确认`、`阻塞`、`降级执行` 必须写明原因和下一步。
- 验证报告和门禁结果必须包含有内容的证据或未验证项；“通过”不能同时含未验证项。未知报告可以结构有效，结构有效不等于检查通过。
- 门禁结果必须说明允许进入阶段或禁止进入阶段。

`validate_agent_output.py` 校验字段、作用域、路径和上述结论/证据结构，不验证命令真实发生或证据真实性。真实执行、当前输入与产物回写由对应质量/能力使用检查器独立核验。

## 专业能力与交接证据

需要专业子能力或跨执行者交接时，按 `capability-index.md` 记录本次计划与实际使用，输出可引用当前项目中的这些记录，不要求每个小任务重复整份JSON。

- 已选择、实际加载和实际使用分别报告，注明能力ID、来源/版本或哈希、负责范围和结果位置。模型角色描述不提供运行、记忆或独立审计能力。
- 交接保留原需求/非目标/未解决约束、准确ID、可写范围、只读依赖、原失败、部分完成、当前证据版本、下一步与停止条件；按需读 `handoff-integrity.md`。必要上下文不能静默截断。
- 人工/模型 `review` 与真实 `execution` 分开：前者可以零发现并列未验证项，后者需要 `universal-quality.md` 的精确argv与当前输入收据。结构化输出可解析不代表内容可信或行为正确。
- 产物回写按明确位置与JSON Pointer独立核对，按需读 `artifact-integrity.md`。检查器结构通过只证明选定字段与范围；已知失败优先报告，缺必需证据为unknown。

专业能力调用成功或交接完成不能改变当前项目验收与整体门禁。阶段/输入变化后只重验受影响结论，保存原失败与修复依据。
