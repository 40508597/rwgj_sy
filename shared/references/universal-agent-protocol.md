# 跨编程智能体通用协议

本协议用于让任意编程智能体（含自研 CLI Agent）按同一套工程约束工作：全部宿主读同一份协议，不维护宿主专用规则文件。它不是外部多智能体运行平台，也不要求宿主原生支持子智能体；最低可用模式是单智能体结构化模拟。

## 最高裁决层

`architecture/` 架构文件夹是唯一真相源。根 `architecture.json` 只是轻量入口；项目目标、验收标准、非目标和用户明确不要必须物化到 `architecture/index.json` 和相关切片，不能作为 JSON 之上的独立自然语言裁决层。智能体必须先把本次任务落位到架构文件夹，再修改代码。

裁决优先级：

```text
用户明确不要
> 安全/数据/不可逆风险
> architecture/ 架构文件夹真相源
> 本次任务范围
> 智能体建议
> 执行速度
```

## 三层执行模式

| 等级 | 适用智能体 | 执行方式 |
|---|---|---|
| Level 1 单智能体结构化模拟 | 只能读提示词/改文件的编程智能体 | 用标准输出块模拟模块视角审议和门禁结果 |
| Level 2 增强单智能体 | 支持文件读写、shell、测试、脚本的智能体 | 在 Level 1 基础上运行校验脚本并记录证据 |
| Level 3 原生多智能体 | 支持 subagents/workers/多会话协作的平台 | 将模块智能体映射为真实执行单元，仍共享 `architecture/` 架构文件夹 |

任何平台能力不足时，必须降级执行并记录原因；降级不能绕过 `architecture/` 架构文件夹、架构先行、验证证据和变更记录。

## 核心组件

- **架构内部目标摘要**：记录最终目标、阶段目标、验收标准、非目标、硬约束、成功证据和失败条件；它必须写入 `architecture/index.json` 或相关切片，不是更高裁决层。
- **动态姿势语境**：记录当前阶段、风险、作用域、模块关系、触发事件、退出条件和追加门禁。
- **功能族引擎**：把需求展开为核心功能、天然绑定、商业标配、待确认扩展、跨模块提案和明确排除。
- **模块智能体协议**：按模块边界组织审议和实现责任。
- **接口契约池**：跨模块协作必须通过接口契约和影响范围分析。
- **硬约束门禁**：用状态门禁阻止跳步、越界、无证据完成。
- **证据账本**：记录自动化测试、人工检查、未验证项、恢复点和变更记录。
- **按需专业能力**：依 `capability-index.md` 用当前需求、模块、风险与姿态选择；CLI规划与宿主实际读取分别记录，不宣称跨平台自动系统提示注入。

## 最小闭环

```text
用户需求
→ 需求落位到 `architecture/index.json` 或相关切片
→ 动态姿势语境
→ 功能族展开
→ 模块智能体提案
→ 接口契约/影响范围
→ 硬约束门禁
→ architecture/index.json 或相关切片变更
→ 代码/文档/测试变更
→ 验证证据
→ 上下文恢复点和变更记录
```

## 平台无关约束

- 不得把协议写成单一平台专用规则。
- 不得因平台没有脚本能力而跳过架构先行；只能记录无法运行工具。
- 不得因平台支持多智能体而让子智能体绕过 `architecture/` 架构文件夹。
- 不得让功能族展开结果直接进入实现；必须经过模块边界和门禁裁决。
- 不得让任何宿主特有的做法覆盖核心协议。

## 智能体能力探测

进入新平台或新项目时，智能体应先识别自身能力；结果只作为执行降级依据，不写成新的项目真相源。

```json
{
  "智能体能力": {
    "可读写文件": true,
    "可运行命令": true,
    "可调用浏览器": false,
    "可维护长期记忆": false,
    "支持子智能体": false,
    "支持规则文件": true,
    "支持工具调用": true,
    "支持结构化输出": true
  }
}
```

## 降级规则

- 无法运行脚本：按文本规则手工检查，并记录“工具未运行”和原因。
- 无法维护长期记忆：必须把恢复点写入 `architecture/tasks/state.json.上下文恢复点`，或写入由 `architecture/index.json` 汇总的恢复点。
- 无法使用子智能体：用结构化输出模拟模块智能体。
- 无法使用浏览器或截图：记录未验证视觉风险或替代检查。
- 无法编辑文件：只能输出变更计划，不得声称已完成实现。

专业技能缺失时可用已有普通能力推进允许的工作，不自动安装；本次必需证据不足为unknown，不能把降级或读取提示当作通过。模型/人工审查、命令执行、截图和字段对账分别说明能证明的范围。完整交付必须按 `universal-quality.md` 配置实际事实并运行 `gate_check --quality-required`；启用专业调用时一并核验计划、实际使用、作用域和回写。

跨平台或跨执行者交接按需读 `handoff-integrity.md`，保留原约束、准确ID、部分失败、当前输入与停止条件；恢复时读取既有恢复点和专业使用记录，不能凭角色记忆续跑。

## 收尾门禁（宿主无关）

本包定义统一的门禁命令与结果契约，具体宿主负责加载技能、调用命令和挂载自动化集成。本包不维护宿主专用规则、钩子或配置；未接入自动化门禁时，智能体必须主动执行以下契约：

> 声明受管项目完整交付前，必须运行 `python "<gate_check_path>" "<项目根>" --quality-required --json`；退出码非 0 时如实汇报未通过项，并把失败项写入上下文恢复点与变更记录。`<gate_check_path>` 由 `resolve_tool.py` 解析得到（JSON 的 path 字段，完整绝对路径），不得再追加脚本名；启动、查看等局部任务只报告本次结果。

通过后结论首行固定为「【任务完成】」，未通过时首行固定为「【未通过验证】」（细则见 `skills/task-architecture/LAYER.md` 完成前自检）。该首行是机器可判的固定契约，供宿主侧自动化检测；它本身不提供拦截能力，模型仍须主动运行门禁。
