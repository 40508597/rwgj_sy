# 硬约束门禁

硬约束门禁用于控制任务状态跃迁。它不是建议清单，而是“未通过则不得进入下一阶段”的裁决机制。

## 门禁结果

```json
{
  "门禁名称": "",
  "结论": "通过 | 不通过 | 阻塞 | 需要确认 | 降级执行",
  "阻塞项": [],
  "必须修复": [],
  "允许进入阶段": "",
  "禁止进入阶段": "",
  "证据": []
}
```

## 必备门禁

| 门禁 | 通过条件 | 未通过处理 |
|---|---|---|
| 占位符门禁 🆕 | 核心字段无 `__待填__` 占位符（运行 `check_placeholders.py` 返回 0）| 不得声明完成，必须填写核心占位符 |
| 进度状态门禁 🆕 | 所有必需阶段已完成（`manage_state.py show` 显示必需阶段 9/9 = 100%）| 不得声明完成，必须完成所有必需阶段 |
| 需求落位门禁 | 本次任务能追溯到 `architecture/index.json` 或相关切片中的功能树、验收标准、模块详情或非目标 | 中止并补充架构落位或询问用户 |
| 架构先行门禁 | 受管项目已先更新 `architecture/index.json` 或相关架构切片 | 不得修改代码，先补架构文件夹 |
| 模块边界门禁 | 新增/修改文件已落到模块树、模块详情和实现清单 | 不得创建或修改未登记文件 |
| 接口契约门禁 | 跨模块调用已登记接口和下游影响 | 不得跨模块直接调用 |
| 功能族裁决门禁 | 功能族候选已分类并裁决纳入/待确认/排除 | 不得把候选直接实现 |
| 风险确认门禁 | 高风险、不可逆、生产、权限、支付、迁移已确认 | 进入阻塞或需要确认 |
| 验证证据门禁 | 完成项有命令、截图、手检或未验证项记录 | 不得声明已完成 |
| 平台降级门禁 | 平台缺能力时已记录降级原因和替代验证 | 不得假装已运行工具 |

### 新增门禁说明（F+B+C 强制执行机制）

**占位符门禁**：
- 检查命令：`python shared/scripts/check_placeholders.py architecture/index.json`
- 分级：核心字段（项目名称、功能树、模块详情等）必须填写
- 强制点：LAYER.md 三重校验第1步，完成前自检硬性要求

**进度状态门禁**：
- 检查命令：`python shared/scripts/manage_state.py show`
- 必需阶段：需求理解、功能树、模块树、模块详情、入口定义、数据拓扑、实现清单、测试责任、验证证据（9 个，含验证证据）
- 可选阶段：接口契约（跨模块调用业务才需要，无则跳过记 skipped）
- 强制点：LAYER.md 第一动作，每完成一个阶段更新

> 真相源：`shared/scripts/manage_state.py` 的 STANDARD_STAGES（required=True 共 9 项）。
> 此前文档误记为 8 个（漏验证证据），已按脚本真相源统一。

## 退出要求

任务最终汇报必须说明哪些门禁通过、哪些降级、哪些未验证。未满足完成定义时，只能汇报“已完成设计/实现，未完成验证”，并写入恢复点和变更记录。
