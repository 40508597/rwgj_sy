# 产物与回写独立核验

用于架构迁移、切片合并、导出转换、生成产物或专业能力回写。本次任务没有转换或产出交接时不增加这项工作。文件哈希只能证明选定字节一致，不能证明转换语义或业务正确。

## 核验方式

1. 固定本次输入、产物路径、预期保留的ID、实体、接口、规则及允许变化，记录检查范围。不要用当前生成结果反过来定义预期。
2. 用独立解析路径读取实际产物：严格解析JSON/YAML/TOML等实际格式，检查条目、引用和正文/代码块是否完整。没有对应解析器时记录该部分未验证；不宣称内置全部格式支持。
3. 比较本次需要的语义：来源与产物的身份/数量、字段值、关联和排除条件；对能力产物与架构回写，按明确的JSON Pointer比较对应值。允许的格式、顺序或换行变化须事先约定，不能掩盖数据丢失。
4. 核验器避免复用待核验生成器的提取函数来计算全部预期，否则同一缺陷可能同时污染输出和断言。独立实现也需验证；对关键保留项使用破坏性负例检查能否识别缺失或错误回写。

## 结果边界

逐项保留通过、失败、未知及原始依据。解析成功、字段相等和哈希相等各证明各自的检查范围，不证明架构决策最优、角色推理可靠或所有路径已测试。按 `capability-index.md` 记录实际使用与回写；要求执行的检查按 `universal-quality.md` 保留本次收据。修复输入或产物后重新核验受影响项。
