# 语义代码审查

用于本次改动涉及状态、错误边界、并发、持久化、权限或公共契约时的专项审查。只看已确认范围；语言、后缀和工程格式不决定是否适用。无法取得可读源码、行为契约或运行证据时说明缺口，不猜测通过。

## 审查重点

- 从入口追踪真实输入、状态变化、输出和失败恢复：非法输入、重复请求、边界值、资源释放与事务失败是否符合契约。
- 检查并发与持久化责任：是否可能重复提交、丢失更新、越权读写或在失败后留下部分状态。先给具体触发条件，再判断严重性。
- 检查公共接口和依赖方向：调用方、参数、返回值、异常及兼容性是否同步；声明的依赖与本次观察到的关系分别记录。
- 对照测试和实际执行结果：哪些结论已有证据，哪些路径尚未覆盖；复杂度、覆盖率、CRAP只能辅助定位，不能代替语义正确性审查。指标阈值来自当前项目规则。

## 产出

每个发现说明位置、触发条件、实际后果、依据和可执行修复建议。区分阻断缺陷、改进建议、风格偏好；没有可复现缺陷可以报告零发现，同时列出检查范围和未验证项。修复后针对受影响结论复核，不预设必须发现几个问题或固定复查轮数。

把审查结论和风险回写到当前项目的验证证据、变更记录或对应模块；按 `capability-index.md` 记录能力实际使用。人工或模型审查报告不冒充自动测试；需要执行证据时按 `universal-quality.md` 运行明确命令并保留本次收据。
