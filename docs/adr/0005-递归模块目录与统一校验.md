# 0005：递归模块目录与统一校验

- 状态：已采纳，行为以实际测试及后续项目使用验证。
- 日期：2026-10-09
- 范围：扩展 0001 的项目事实位置，保留能力与项目状态分离。

## 背景

长期项目持续增长时，AI 需要按功能逐层定位，而非每次完整读取全部架构。
用户要求技能指导实际模块目录的建立：每模块一份架构文件，可包含任意有限深度的子模块。
架构记录还需承载语义、契约、决策、实现及验证，支持换执行者继续工作。

## 决策

1. 新项目使用根 `architecture.json` 和各模块目录内的 `architecture.json`。
   每层的 `模块路由` 以稳定编号和相对当前目录的路径登记直接子模块。
   根及中间模块都能拥有自己的源码；目录不预设层数，普通资源目录不自动成为模块。
2. 模块详情和实现清单归所属模块；实现路径统一为项目根相对路径。
   父节点记录定位说明，子模块的完整定义只有一个维护位置。
   全局目标、项目恢复点和专业能力状态由根维护；局部补充事实按模块保存。
3. 局部读取和全量校验是不同操作。日常沿根路由展开当前任务相关分支；
   完整验证遍历已登记模块，检查丢失路径、重复编号、归属冲突与实际实现。
4. 包含树不产生依赖边。跨模块影响仍依据模块拓扑、接口、数据和验证责任检查。
5. 统一加载器为既有结构、质量、子技能、漂移和可视化消费者提供只读合成视图。
   物理架构文件保持事实所有权；派生模块目录不可在源文件中手工维护。
6. 已有集中切片布局保留完整读取与验证。纳管依据现有代码布局，调整目录时必须核对
   构建、导入、资源与交付路径，不为了文件形式搬动已有实现。
7. 工具负责确定性操作，AI 负责语义理解和方案判断。局部更新携带当前文件哈希，
   输入变化时拒绝覆盖；工具成功不代表设计合理、业务正确或验证完成。
8. 根声明未登记架构盘点的持久排除目录，所有校验入口使用同一范围；临时查询选项
   不修改全局范围，也不豁免已登记实现。协调修改父子入口采用批量补丁，先预检
   全部摘要与候选树，再串行写入并处理失败恢复；仍须协调共同文件的写入责任。

## 比较与后果

全部架构集中保存，工具简单但真实模块与架构位置分离；根维护所有下层摘要又会增加
同步成本。采用邻近模块文件和逐级入口，能够局部阅读，但必须处理父子引用、唯一所有权、
孤儿模块和跨分支影响。共享加载视图保留原质量能力，避免维护两套强弱不同的验收规则。

新增工具仍需完整检查时遍历项目，不能承诺所有查询都是常数开销。深层目录受实际
文件系统和运行资源限制，协议自身不设置固定层数。任意语言均能登记目录、契约和文件；
代码行为检查仍使用本次实际可用的采集器、构建与测试，不把未采集范围当作通过。

## 验证与重新评估

验证原有全套用例，并增加 Unicode 路径、父模块源码、深层路由、跨枝依赖、孤儿模块、
哈希冲突、缺失实现和可视化内容保留检查。独立试用记录真实生成物与失败，不靠填写字段评分。
如果项目使用中暴露重复事实维护、定位读取过量或协作冲突，应针对对应操作调整协议与工具。
