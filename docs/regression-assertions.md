# 回归断言

这些场景用于判断任务架构能力是否被稀释。断言失败表示不能交付。

> 质量红线工具化：以下断言中的「导出功能」「管理类能力」「菜单栏」等可机械化检查的
> 场景，已由 `shared/scripts/check_quality_redlines.py` 自动执行（操作类节点缺异常路径、
> 批量/导出类缺安全信号、叶子不可验收、空壳模块）；本文件仍保留完整文本断言作为
> 人工审计（`audit_architecture.py`）的检查依据。

## 导出功能

必须出现并归位：

- 字段映射或导出范围。
- 权限校验。
- 大数据量处理。
- 失败恢复。
- 审计或导出记录。
- 测试责任。

## 管理类能力

不得把管理能力塞进普通用户页面。必须判断：

- 是否需要独立入口。
- 是否需要独立权限边界。
- 是否需要独立模块或子模块。
- 是否涉及数据维护、审计或运营反馈。

## 菜单栏

不得只生成横条。必须覆盖：

- 菜单项行为。
- 点击后的动作、反馈和失败处理。
- 激活/禁用/加载/错误状态。
- 下拉或层级关系。
- 路由、命令或动作绑定。
- 快捷键、键盘或可访问性需求（适用时）。

## 修 Bug

必须补：

- Bug 场景。
- 异常路径。
- 复现或验证方式。
- 测试责任。
- 变更记录。

## 小命令降级

最小闭环不得稀释为「完全跳过功能簇」或「无验证直接改」。断言场景输入为
`detect_small_command.py --request '修改某个元素' --project-root <受管项目>` 的 JSON 输出：

- 有效档位必须为「最小闭环」。
- 必须动作必须含「功能簇最小定位」（不得完全跳过功能簇）。
- 修改类必须动作必须含「三重校验」。
- 完全跳过档回执必须声明「使用普通编程智能体能力处理」。
- 高风险词必须升档完整流程或至少带风险等级信号。

## 新增模块

必须落位：

- 功能树。
- 模块树。
- 模块详情。
- 接口契约。
- 实现清单。
- 测试责任矩阵。
