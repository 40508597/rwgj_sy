# 工具链维护与已有工具接口

本文件维护工具的职责、返回值含义和检查边界。实际文件、源码摘要、函数签名、参数和子命令以 `shared/scripts/check_toolchain_inventory.py` 从当前源码生成的清单为准；不在文档或入口重复维护脚本数量。

## 维护检查

在能力包根目录运行以下命令，结果始终为 JSON：

```text
python shared/scripts/check_toolchain_inventory.py --json
python shared/scripts/check_toolchain_inventory.py --verify-help --json
python -m unittest discover -s tests -p test_toolchain_maintenance.py -v
```

第一条只读取文件并解析 AST，不导入被盘点模块，不执行项目代码，不创建调用方架构或状态。它根据实际 `.py` 文件生成 SHA256、用途、主入口保护、公共函数和类方法签名、本地依赖、参数声明、子命令和候选测试。新增文件没有维护约定会得到 `unknown`，语法错误、重复函数覆盖、缺失入口保护和本地核心依赖矛盾会得到 `fail`；空目录不会通过。

第二条显式信任当前能力包，对已登记且静态审阅通过的公开 CLI 执行 `--help`。帮助在空临时目录运行，关闭字节码写盘并检查临时目录是否留下文件；每份回执保留真实返回码、stdout、stderr 和当前源码摘要。自定义 `--scripts-dir` 禁止执行帮助，防止盘点时运行一个冒用熟悉文件名的外部脚本。临时工作目录不是系统沙箱，帮助 smoke 也不是完整业务测试。

`test_candidates` 仅表示测试文件中有实际脚本标识的引用，不代表这些测试已经运行、覆盖了所有分支或证明了正确性。动态循环构造的参数会保留原表达式，不伪装成已经执行展开的结果。维护时继续运行完整测试和真实项目路径，不能用清单绿灯替代它们。

## 共用底座与新增工具链

| 文件 | 职责与权威范围 | 接口与验证重点 |
|---|---|---|
| `_archlib.py` | UTF-8、严格 JSON、指针/切片/模块合成、IO 和状态聚合 | 函数 API。重复键、非有限数、路径外逃和缺失事实不得静默通过；失败优先于未知。 |
| `_module_tree.py` | 任意有限深度的物理模块树、归属、模块目录和局部事实 | 函数 API。包含树与依赖图分离；稳定编号、跨模块文件归属、孤儿和原始数据保留。 |
| `_architecture_visual.py` | 原始事实到完整可视化模型的无损投影 | 函数 API。每项物理事实可定位；原始值类型和空容器保留；引用歧义单独诊断。 |
| `_capabilitylib.py` | 专业能力 catalog、规划和路径校验 | 函数 API。实际任务事实驱动选择，缺前置事实保持未知；不自动执行或安装技能。 |
| `_toolchain_query.py` | 对象索引、定位、展开和工作上下文 | 函数 API。保存物理所属文件、JSON Pointer 和内容摘要；查询不另建权威缓存。 |
| `_toolchain_store.py` | 调用方 SQLite 状态、修订号、事件链和内容快照 | 函数 API。只读打开不能隐式创建状态；事务序列化协作工具的元数据写者。 |
| `_toolchain_changes.py` | 变更依据、暂存、预览、应用、验证和接受 | 函数 API。检查过期依据；架构先于对应源码写入；接受必须有当前通过证据；恢复不覆盖他人修改。 |
| `_toolchain_runtime.py` | 模块责任、交接、运行、暂停、检查点与时间线 | 函数 API。父子范围冲突、过期租约、交接过期、恢复前像及事件细节。登记不是 OS 隔离。 |
| `taskarch.py` | 新工具链统一操作入口 | JSON 信封区分 `operation`、`status`、`code`、`data`、`evidence`、`limitations`。`pass/0`、`fail/1`、`unknown/2`。操作成功不等于任务验证或变更接受。 |
| `taskarch_cli.py` | 原有确定性操作聚合入口 | 保留原有分档、姿态、进度和门禁子命令；新工具链不借旧接口改变现有调用者含义。 |
| `resolve_tool.py` | 项目与安装目录工具定位 | 只返回路径，不执行工具。新增入口需可解析；缺失结果不能冒充成功。 |

这些工具处理项目声明和不透明源码字节。特定语言的导出接口、调用关系、复杂度和覆盖率由项目原生分析器提供；没有采集能力时保留未验证，不声称自动理解所有语言。

## 已有独立工具逐项约定

所有公开入口支持 `--help`；完整参数和实际子命令由动态清单读取。表中的返回值保留既有独立 CLI 语义，不能把所有脚本的 `1` 都解释为同一种工程失败。

| 工具 | 用途与输入 | 返回值和范围 |
|---|---|---|
| `module_architecture.py` | `init/add/read/route/search/impact/check/update/update-batch`；根/模块架构及显式补丁 | `0` 操作成功，`1` 已知结构或写入冲突，`2` 输入未知。局部和批量更新按被审阅文件 SHA 预检；不是多写者强事务。 |
| `init_architecture.py` | 新建集中切片架构或迁移旧完整单文件 | `0` 创建，`1` 已有文件冲突，`2` 不可用输入。迁移先保留原字节档案；`--force` 是明确覆盖指令，没有过期写入事务保证。递归新建优先使用模块工具。 |
| `manage_state.py` | 阶段、阻塞项、下一步、修订号和状态显示 | `0` 操作成功，`1` 缺状态/不适用操作，`2` 输入错误，**`3` 修订冲突**（保留旧约定）。文件锁覆盖完整状态事务；完成率从阶段派生。状态完成不等于实现验证通过。 |
| `detect_should_trigger.py` | 受管锚点与目录规模建议；默认当前目录，可指定 `--project` | `0` 建议接管或评估，`1` 不建议，`2` 自动检测关闭或输入不可用。规模只是建议，不将文件自动认定为业务源码。 |
| `detect_small_command.py` | 需求文本和分档规则 | `0` 生成分档建议，`2` 输入不可用。它决定适用路径的候选，不证明任务简单或已经完成。 |
| `detect_task_posture.py` | 需求、姿态和风险词规则 | `0` 生成候选建议，`2` 输入不可用。不得将关键词匹配当作语义真相。 |
| `plan_capabilities.py` | 当前架构、上下文事实、catalog 和宿主能力 | `0` 完整计划，`1` 非法输入，`2` 前置事实不足（保留旧约定）。返回计划不等于正文加载，宿主必须真实读取被选文件。 |
| `check_capability_usage.py` | 计划、实际阅读摘要、使用审查和 JSON 回写记录 | `0` 一致，`1` 明确矛盾，`2` 缺证据或输入错误。不证明审阅者身份或工程结论。 |
| `check_subskill_sources.py` | 本地来源锁、导入字节和 catalog 绑定 | `0` 本地一致，`1` 明确违反声明，`2` 输入不可用。锁不是远程签名，也不认证作者或许可证权利。 |
| `check_placeholders.py` | 架构和 schema 分级；可启用 `--strict` | `0` 核心完整，`1` 核心缺项或 strict 下存在其他缺项，`2` 读入失败。默认核心通过不表示重要字段全部完成。 |
| `validate_architecture.py` | 合成架构的字段、引用、模块、归属及契约结构 | `0` 结构通过，`1` 确定违规，`2` 输入不可用；警告需阅读，结构通过不等于设计正确。 |
| `check_quality_redlines.py` | 功能树、入口、安全可靠性信号和当前证据复核 | `0` 适用项通过，`1` 违反红线，`2` 证据未知。启发式误报通过绑定当前条目与证据的复核处理，不能批量加关键词清零。 |
| `check_project_quality.py` | 明确质量规则、事实、来源文件哈希和执行收据 | `0` 必需规则通过，`1` 必需规则失败，`2` 观察未知。保留依赖/环/度量/CRAP/执行/决策/接口检查；缺采集器不以空事实冒充通过。 |
| `run_verification.py` | 项目、显式输入、超时、输出收据和 `--` 后原样命令 argv | `0` 当前执行通过，`1` 执行失败，`2` 超时或证据未知。输入 SHA 必须新鲜；超时只终止顶层进程，不保证外部副作用恢复。 |
| `run_quality_probes.py` | 显式测试套件、原始字节补丁和检查命令 | 对副本先跑通过基线再跑故障；只有预期检查失败才记检出。副本不是系统沙箱；原项目字节必须不变。 |
| `scan_code_drift.py` | 项目及实际文件盘点；可按任意后缀或所有常规文件 | `0` 无漂移，`1` 声明缺失或存在未登记文件，`2` 无法盘点。所有声明路径都会核查；不判断源码语义。 |
| `diff_architecture.py` | 两个架构入口；类型敏感字段差异 | `0` 相同，`1` 有差异，`2` 输入错误。`1` 不是质量失败；JSON 完整返回，文本显示明确截断数量。 |
| `render_architecture.py` | 架构入口、视图和显式输出路径 | `0` 输出成功，`2` 输入/输出失败。`--output` 可以覆盖其指定的既有视图文件，不提供版本事务；成功只表示只读模型生成，架构与源码不能被渲染修改。完整信息与浏览器可用性分别验证。 |
| `audit_architecture.py` | `generate` 生成问卷；`report` 核验填写结果 | `0` 生成或报告通过，`1` 缺项/不通过，`2` 输入不可用。每个 yes/no 需要证据，na 需要适用性理由；拒绝重复问题和重复 JSON 键。 |
| `validate_agent_output.py` | agent-output schema 和智能体结构化输出 | `0` 结构通过，`1` 结构违规，`2` 无法核验；不将规范化结论当作真实验证。 |
| `validate_protocol_semantics.py` | 项目及能力分发的可移植协议基线 | `0` 基线满足，`1` 基线违规，`2` 输入未知；不代替全部业务架构或代码质量门禁。 |
| `judge_progress.py` | 架构、实际阶段状态与三项事中裁判 | `0` 可以继续，`1` 当前阶段失败，`2` 无法验证。读取结构化检查结果，不通过输出关键词猜成功。 |
| `gate_check.py` | 项目、收尾阶段和显式适用质量/能力要求 | 聚合适用检查：失败优先，然后未知，全部通过才通过。门禁与独立红线共用评估结果。 |
| `check_regression_assertions.py` | 历史场景与输出文本 | `0` 关键词完整，`1` 缺词，`2` 文本不可用。文本关键词回归不能替代语义审查或业务断言。 |
| `run_with_progress.py` | 同目录公开脚本文件名、显示说明、原样参数 | 人工输出包装：子工具 `0` 映射成功，其余映射包装器 `1`；不供三态门禁聚合使用。外部、私有、递归自调用和链接脚本路径被拒绝。 |
| `check_toolchain_inventory.py` | 当前实际 Python 文件及可选受审帮助 smoke | `0` 维护检查通过，`1` 确定矛盾，`2` 未审阅或不可用；不根据静态数量或仅有测试文件就声称功能通过。 |

## 本轮具体维护修复

- 模块读取、局部补丁、批量补丁、进度状态、初始化模板、旧架构迁移、独立审计和能力规划读取统一复用 `_archlib.strict_json_loads`；嵌套重复键、NaN/Infinity 和溢出为无穷大的数不会静默进入写盘或审核。专门测试确认非法迁移在创建档案/输出之前终止，非法模块补丁不写任何目标。
- 人工进度包装器只执行同目录公开 Python 工具；保留说明和参数顺序及失败输出，新增标准帮助。它仍保留原人工包装的二值成功语义，不冒充结构化门禁。
- 触发建议新增标准帮助和可选项目路径；默认仍盘点当前目录。帮助在自动触发关闭时也正常显示；不存在项目返回不可用。
- 关键词回归的不可读文本返回 `unknown/2`，JSON 模式保留可解析错误；真实缺词仍为 `fail/1`，齐全仍为 `pass/0`。
- 架构差异文本的负显示上限归零并明确截断，JSON 数据完整；删除架构校验器重复的常量定义，避免未来两处漂移。
- 渲染输出继续保护架构、状态等权威输入，并补充登记源码保护与输出前输入摘要重核。真实 CLI 测试验证输出指向架构或不透明源码时拒绝且字节不变，正常 HTML 输出保持可用。
- 渲染输入快照的读取错误返回不可用；原本不存在的登记源码在渲染中出现，也使该次输出失效，避免生成依据已变化的视图。
- 变更迁移跨父模块时同步显式模块树、真实路由和已声明路径，同时保留源码字节与无关业务字面量。缺失文件也是版本依据，验证期间出现及接受前变化均会阻断；范围扩展必须保留原模块和暂存新模块。

## 后续维护要求

新增或修改工具时同时维护用途/范围约定、输入错误、明确失败、未知、当前版本检查、真实副作用和针对性回归。参数或写入语义变化要更新调用方文档与统一入口，而不是只让 `--help` 变绿。先跑维护测试和受审帮助，再跑现有完整测试、来源锁检查、分发验证及真实项目路径；并发和中断承诺必须用对应场景验证。工具链元数据只能写在调用方项目，不得把业务状态写回能力包。

### 发布基准与实际收益

维护仓库或开发分发使用 `scripts/benchmark_long_task.py --skill-root <技能根> --output <仓库外报告>` 重放固定长程场景；同一脚本可分别指向冻结基线与候选版本。报告保留每步真实命令、退出码、输入摘要和原始输出，统计伪接受、重新协调、恢复耗时及实际上下文字节。工具重放检验流程不变量，不等于 AI 在未知业务上的开发成功率；后者另用未参与优化的任务及独立审查衡量。耗时和读取量保留实测值，不作为所有项目的固定阈值，不用字节冒充 token。

发布验收复用现有 CI 矩阵，不再搭第二套规则引擎：先核验 Node 示例运行时实际可用，再运行原回归与自检；运行版、开发版分别构建和验证，逐文件摘要核对当前源码。完整长程重放只在一个明确环境额外执行，避免每个矩阵重复同一批次。分发哈希标识精确载荷，旧版和候选版结果分别保留；构建成功、来源锁一致或测试数量增加，各自不替代实际任务验收。
