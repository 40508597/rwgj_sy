# Project Depth Core

本技能负责”想得深”，不负责协议层与工具门禁。

第一原则：

```text
用户描述的是想要什么，AI 的职责是思考它在真实软件中应该是什么。
```

## 当前任务与进度

沿用 LAYER 已判定的任务范围和已有阶段状态，不因进入本层重复读取或展示同一状态。设计批次真实完成后按 [LAYER 收尾校验](../task-architecture/LAYER.md#工具与完成契约) 推进阶段；工具与阶段清单由该入口统一约定。

## 六大机制

默认标准展开按 `../../shared/references/function-clusters.md` 呈现核心、天然绑定、适用商业标配、强相关衍生与关联功能的全景，由用户取舍。最小交付条件、分批实现和专业资料读取预算不限制功能发现；只在用户明确限定或记录不适用依据时裁减相关项。

1. **最大主动性设计**：主动补全安全、日志、错误处理、健康检查、迁移、测试、部署和可维护性关注点。
2. **功能簇展开**：一个功能名是一组天然绑定能力，不得把菜单栏做成横条、把导出做成按钮、把后台做成普通页面。
3. **交互完整性**：本轮纳入和已实施的每个操作必须覆盖请求、处理中、成功反馈、失败处理、异常恢复；候选范围按功能簇协议记录，不把未实施设计当作已完成。
4. **多层递进设计**：先全景，再骨架，再逐块深度设计，再集成验证。
5. **分治设计法**：大功能拆小块，每块设计到不熟悉项目的人也能独立实现。
6. **实现期循环展开**：功能簇展开不是只发生在设计阶段。写代码过程中一旦发现缺状态、异常路径、权限边界、数据字段、接口契约或验证责任，必须暂停编码，围绕当前功能节点局部回展开功能簇，分类裁决（必须补/建议补/待确认/明确排除），先更新所属模块架构或集中切片再继续编码。

## 强制展开停止规则

功能簇展开不是列一级功能名。每个叶子节点必须满足以下任一条件才允许停止：

- 是单一可测试操作：有明确输入、输出、成功标准和异常路径。
- 是不可拆解的外部事实：第三方协议、硬件限制、法规要求或平台限制。
- 已明确排除，并记录排除原因。
- 是尚未实施的待确认、延期或不适用候选，已记录本轮取舍理由、尚待裁决的问题或后续继续条件；保留完整功能全景，不强制补齐实施细节。范围判定以 [候选状态与本轮实施范围](../../shared/references/function-clusters.md#候选状态与本轮实施范围) 为准，已有实施证据不因改状态免检。

本轮纳入项不满足可实施条件则继续展开。

## 架构归位前置

任何功能进入实现前，必须先判断：

- 功能本体是什么。
- 它拥有或改变什么状态。
- 它依赖哪些上游能力。
- 它影响哪些下游能力。
- 它不应该放在哪里。
- 它应该落到功能树、模块、入口、接口、数据、页面、任务、测试中的哪些位置。

归位不是一次性动作。进入逐块实现后，写代码过程中若发现这六个判断有缺口（少了状态、依赖、落位或边界），同样要暂停编码、回到归位判断、更新架构切片，再继续。设计期和实现期共用同一套归位标准。

## 从职责设计到实际模块目录

新项目先充分展开功能与约束，再按职责、状态/数据归属、对外契约和测试边界决定模块目录；目录设计不能反过来限制功能发现。比较必要候选并记录理由后，才创建根总架构、模块目录和本模块架构。业务模块可先有已确认的职责、契约与路由骨架，未知细节明确保留为待设计，不将空骨架当作已实现。

受管模块可包含任意数量的子模块，任意一层可拥有实现和测试；没有固定层数或文件数标准。仅为公共工具、资源或构建组织而存在的普通目录，不必升级为模块。按需读 [递归模块架构](../../shared/references/recursive-modules.md)。

修改任务先从根按职责逐层定位，可探索多个相关分支；再核对目标源码、测试、依赖和消费者。位置正确仍需设计判断。跨模块需求确定主要模块与协作模块，不把全部功能塞入最先找到的位置。上层保持全局约束和必要路由摘要，下层维护局部完整事实；当前有效事实、待实施设计与历史证据分别标明，防止接手者把计划当实现。

## 智能关联路由

涉及模块边界、数据归属、运行形态、技术选型或关键质量目标时，先明确真实驱动与硬约束，比较合理候选，记录收益、代价、接受的负面后果、验证方式和重新评估条件。把可执行约束转成依赖/质量/验收规则；记录完整不代表方案适合。按需读取 `../../shared/references/universal-quality.md`。不编造规模或 SLO，不为小任务强制全面决策记录。

修改一个节点时，沿架构牵引链自动联想：

```text
功能 → 模块 → 接口 → 下游调用 → 入口/页面 → 数据 → 测试 → 变更记录
```

联想出来的是检查项，不是自动实现项。必须逐项判断是否真的受影响。

需要专业能力时先按当前功能节点、已确认需求和可用性选择，再按姿态与阶段读取 `../../shared/references/capability-index.md` 的对应资料。专业技能可以帮助设计与审查，不得替代功能裁决、扩大业务范围或凭角色身份断言结果。没有对应技能可继续允许的普通工作，必需验证仍需真实证据。
