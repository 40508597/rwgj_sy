# Project Depth Core

本技能负责“想得深”，不负责跨平台适配和工具门禁。

第一原则：

```text
用户描述的是想要什么，AI 的职责是思考它在真实软件中应该是什么。
```

## 五大机制

1. **最大主动性设计**：主动补全安全、日志、错误处理、健康检查、迁移、测试、部署和可维护性关注点。
2. **功能簇展开**：一个功能名是一组天然绑定能力，不得把菜单栏做成横条、把导出做成按钮、把后台做成普通页面。
3. **交互完整性**：每个操作必须覆盖请求、处理中、成功反馈、失败处理、异常恢复。
4. **多层递进设计**：先全景，再骨架，再逐块深度设计，再集成验证。
5. **分治设计法**：大功能拆小块，每块设计到不熟悉项目的人也能独立实现。

## 强制展开停止规则

功能簇展开不是列一级功能名。每个叶子节点必须满足以下任一条件才允许停止：

- 是单一可测试操作：有明确输入、输出、成功标准和异常路径。
- 是不可拆解的外部事实：第三方协议、硬件限制、法规要求或平台限制。
- 已明确排除，并记录排除原因。

不满足则继续展开。

## 架构归位前置

任何功能进入实现前，必须先判断：

- 功能本体是什么。
- 它拥有或改变什么状态。
- 它依赖哪些上游能力。
- 它影响哪些下游能力。
- 它不应该放在哪里。
- 它应该落到功能树、模块、入口、接口、数据、页面、任务、测试中的哪些位置。

## 智能关联路由

修改一个节点时，沿架构牵引链自动联想：

```text
功能 → 模块 → 接口 → 下游调用 → 入口/页面 → 数据 → 测试 → 变更记录
```

联想出来的是检查项，不是自动实现项。必须逐项判断是否真的受影响。
